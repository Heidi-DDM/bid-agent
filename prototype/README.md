# 投标智能体 · 可点击原型（R011 / F010）

> 对应需求：R011（可点击原型与目标用户验证）｜ 规格：`docs/03-功能规格/F010-投标准入原型与用户验证.md`
> 状态：Iteration 2 交付，供 Iteration 3 用户验证使用

## 一、这是什么

纯静态可点击原型（HTML/CSS/JS，无构建、无后端、无依赖），用**脱敏真实案例**演示投标智能体「满分才进投标审批」的最小闭环用户旅程。原型只用于用户验证流程与评分规则，**不实现真实计算引擎、不接数据库、不做权限系统实现**（F010 §2）。

## 二、如何运行

任意静态服务器即可，例如：

```bash
cd prototype && python3 -m http.server 8080
# 浏览器打开 http://localhost:8080
```

直接双击 `index.html` 也可浏览（页面间跳转使用相对路径）。

## 三、用户旅程（7 步，与 F010 §3 一致）

| 步骤 | 页面 | 说明 |
|---|---|---|
| 1 | `index.html` | **首页入口 = 新建投标准入任务**（验收硬性要求）；现有任务列表 |
| 2 | `import.html` | 新建任务表单（项目名称/URL/上传招标文件/粘贴正文）+ 原文与解析状态（不可变、多版本、sha256、澄清挂接） |
| 3 | `matrix.html` | 招标要求矩阵：hard/scored/action 三类 tab；点击任意行打开**字段级证据抽屉**（条款引用 + 企业证据 + 原文摘录） |
| 4 | `materials.html` | 公司资料选择：资质/安许证/项目经理名录（主推荐/备选、active/expired/pending_verification） |
| 5 | `score.html` | 满分评分面板：四类结论、硬条件 12 项、计分项、动作项、报价边界；文案“满分 ≠ 自动投标” |
| 6 | `queue.html` | 阻断/待补/复核三类队列（blocked_hard_requirement / blocked_missing_data / manual_review） |
| 7 | `approval.html` | 待投标审批 → 审批/驳回（意见必填）/豁免表单/审计时间线；**非审批角色访问显示 403** |
| — | `exceptions.html` | 5 类异常态演示：空态 / 资料过期 / 解析失败 / 权限不足 / 无合格项目经理 |

右上角**角色切换器**（投标专员/数据管理员/经营负责人/法务）模拟登录，切换后审批页权限随之变化。

## 四、数据口径

- 主旅程数据 = `验证受限材料/农大/`（河北农业大学东校区研究生宿舍建设项目施工，事后验证样本，已中标）
  - 20 条规则与 `scripts/matching/golden_requirements_nongda.json` 一致（hard 12 / scored 4 / action 4）
  - 匹配矩阵与 `nongda_match_result.json` 一致：hard 11/12 satisfied、NQ-H-007 待补（财务审计素材缺口）、主观 2 项人工复核、客观类似业绩双 satisfied（2.5+2.5）
  - 审批记录与 `approval_demo_result.json` 一致；**待审批条目为补齐材料后的构造口径，仅用于演示审批流**
- 异常态案例：康保储能 EPC（空态）、广宗葫芦中学（资料过期）、阜平高铁片区管网（解析部分完成）、无合格经理（构造）
- 所有名称按 F007 §6.4 脱敏；本项目目录 Git 白名单内（`prototype/` 可提交）

## 五、业务红线在原型中的体现

1. 满分 ≠ 自动投标：评分面板与审批页均有明确文案，最终决定由经营负责人完成（ADR-001 §2.3）
2. 数据缺失默认阻断：NQ-H-007 显示“待补/不可判定”，不推断满足
3. 硬性缺项一票否决：广宗案例展示 expired → blocked_hard_requirement
4. 无合格项目经理：候选 0 人 → 准入阻断，不生成不存在的经理
5. 纯事实红线：导入/解析页只展示原文事实与解析状态，无分析断语
6. 审计留痕：审批/驳回/豁免全部动作记录谁/何时/依据/结论
