# 11-部署方案：阿里云演示环境（外部人员访问）

- **状态**：v1.0（2026-09-11）已实施 ｜ **关联**：F018（运行时技术基线）、F020（API/权限）、R012（原型接入真实 API）、ADR-001
- **目标**：把当前 API + worker + PostgreSQL + 原型前端以 Docker 方式部署到阿里云 ECS，给外部人员一个可登录的网页地址做检查与试用；同时建立"本地改代码 → 一条命令同步到服务器"的维护流程。
- **用户决策（2026-09-11）**：① embedding/reranker 模型服务**暂不上服务器**；② 外部人员只看**脱敏数据**；③ 部署在服务器账号 `qykj_lqf` 的家目录下。

> 服务器登录凭据见 `docs/阿里云服务器配置信息/阿里云配置信息.docx`（已被 `.gitignore` 的 `*.docx` 规则排除，**不得**改名为可提交格式）。本文件不记录任何密码/令牌。

## 1. 边界与非目标

- 这是**演示/验收环境**，不是生产环境：单机、无高可用、无自动备份策略（提供手动备份命令）。
- 不部署 embedding 服务 → `PGVECTOR_ENABLED=false`，RAG 索引/检索按 F025 §7 **可解释降级**：`knowledge_index` 任务明确失败（不伪造成功）、匹配执行器记录 `rag_degraded`，**规则引擎驱动的 7 步旅程（搜索→导入→解析→确认→匹配→风险→补录重算→审批）不受影响**。
- 不预置任何真实企业资料原件与招标文件原件；企业结构化演示数据经脱敏后导入（§6）。
- 沿用 F018 §6 红线：数据库端口不对公网开放；DeepSeek 关闭；`AUTH_DEV_HEADERS` 不开启（X-Role 伪装头在服务器上无效，必须登录）。

## 3. 部署形态

```text
外部人员浏览器 ──http://8.163.107.248:2000──▶ [nginx 容器]  静态原型页 prototype/
                                                │           /api/*、/healthz、/readyz → 反向代理
                                                ▼
                                          [api 容器]  uvicorn runtime.api:app :8000（容器网络内）
                                                │
                     [worker 容器] python -m runtime.worker ──┤
                                                ▼
                                          [db 容器]  pgvector/pgvector:pg16 :5432（仅容器网络内）
                                                │
                                   数据卷：pgdata（数据库）、./data/objects（不可变原文对象）
```

- **同源**：前端与 API 同一个入口（nginx），无需 CORS；`APP_ENV=prod` 下 API 本身不加 CORS（fail-closed）。
- api / worker / migrate 共用同一个镜像 `bid-agent-runtime`，仅启动命令不同。
- `migrate` 是一次性容器：`alembic upgrade head` 成功后 api/worker 才启动（`depends_on: service_completed_successfully`）。

## 4. 镜像与依赖裁剪

- 基础镜像 `python:3.12-slim`（F018 要求 3.11+；本机 3.14 开发，代码无 3.13+ 专属语法）。
- 系统包：`poppler-utils`（pdftotext/pdftoppm）、`tesseract-ocr` + `tesseract-ocr-chi-sim`、`libpq5`。
- Python 依赖使用 `deploy/requirements-server.txt`：在 `requirements-dev.txt` 基础上**去掉** `torch`、`sentence-transformers`（仅 embedding_serve 使用，运行时代码无引用；两者体积数 GB），保留 `pgvector`（`runtime/db/models.py` 模块加载需要）。
- pip 走 `mirrors.aliyun.com`，apt 走阿里云 Debian 镜像。
- 构建期执行 `python -m compileall runtime scripts/matching` 做语法门禁。

## 5. 环境变量（`deploy/.env`，模板见 `deploy/.env.example`）

| 变量 | 服务器取值 | 说明 |
|---|---|---|
| `APP_ENV` | `prod` | 关闭 `/docs`、不加 CORS、不启用 X-Role 回退 |
| `DATABASE_URL` | `postgresql+psycopg://bid_agent:<口令>@db:5432/bid_agent` | 指向容器网络内 `db` |
| `OBJECT_STORE_ROOT` | `/data/objects` | 容器内路径，绑定到宿主 `data/objects/` |
| `BIND_HOST` / `BIND_PORT` | `0.0.0.0` / `8000` | 仅容器网络内可达，不发布到宿主 |
| `PGVECTOR_ENABLED` | `false` | 无 embedding 服务，索引/检索显式降级 |
| `MODEL_BASE_URL` | 留空 | 模型适配器未启用，`/readyz` 跳过模型检查 |
| `DEEPSEEK_ENABLED` / `DEEPSEEK_PUBLIC_ONLY` | `false` / `true` | 不用外部模型 |
| `OCR_LANG` | `chi_sim` | 容器内已装 |
| `AUTH_USERS` | 4 个演示账号（pbkdf2 哈希） | 角色：bid_specialist / data_admin / business_head / legal |
| `AUTH_TOKEN_SECRET` | 随机 48 字节 | token 签名 |
| `POSTGRES_PASSWORD` | 随机 | 仅 db 容器与 `DATABASE_URL` 使用 |

账号明文口令只在交付时线下告知负责人，**不写入任何文档与 Git**。

## 7. 维护与更新流程（`deploy/sync.sh`）

```bash
# 本机执行；首次与后续更新都是同一条命令
bash deploy/sync.sh            # rsync 代码 → 服务器 build → alembic upgrade → compose up -d → 健康检查
bash deploy/sync.sh --no-build # 仅同步静态前端/配置并重启（改了 prototype/ 时更快）
```

rsync 排除（与 Git 白名单同口径）：`.git/ .venv/ __pycache__/ raw/ logs/ runtime/objects/ runtime/.env 推送日志/ 企业资料台账20260821/ 验证受限材料/ embedding_serve/ ppt_build/ *.docx *.pptx *.pdf *.xlsx *.html(根目录汇报) 情报库/ 报告/ 质量报告/ 评测任务/ 竞品调研/ 会议纪要/ daily/ reports/`。

常用运维命令（服务器上，目录 `~/bid-agent/app`）：

```bash
sudo docker compose -f deploy/docker-compose.yml --env-file ../deploy/.env ps          # 状态
sudo docker compose -f deploy/docker-compose.yml --env-file ../deploy/.env logs -f api  # 日志
sudo docker compose -f deploy/docker-compose.yml --env-file ../deploy/.env exec db \
  pg_dump -U bid_agent bid_agent | gzip > ~/bid-agent/backups/bid_agent_$(date +%F).sql.gz  # 备份
```

回滚：`git checkout <上一个提交>` 后重新 `bash deploy/sync.sh`（镜像按代码重建；数据库结构如有降级需求需手工 `alembic downgrade`，演示期不承诺）。

## 9. 已知限制与后续事项

- `.doc`（旧版 Word）解析依赖 macOS `textutil`，Linux 容器内不可用 → 该格式任务会进入可解释失败；PDF/图片 OCR 正常。
- 无 HTTPS、无域名：演示期通过 IP:端口 访问；若后续绑定域名并开放 80/443，国内服务器需先完成 ICP 备案。
- 单 worker、无并发承诺；招标文件上传上限由 nginx `client_max_body_size 200m` 控制。
- 实时公告搜索依赖服务器出网与各平台对云 IP 的访问策略（`COLLECTION_POLICY` 缺省 `production`，与本地一致）。
- 容器内日志时间为 UTC（比北京时间早 8 小时）。
- 服务器上装了 `rsync`（`dnf install rsync`，sync.sh 依赖）；首次登录时已将本机 SSH 公钥写入 `~/.ssh/authorized_keys`，后续免密。
- 内置浏览器自动化对本页面的 Playwright `click()` 会超时（页面 JS `.click()` 与真人点击正常），属自动化工具兼容问题，不影响用户使用。
- **待用户决策**：① 农大招标文件 PDF 是否预置为演示样本（§6）；② 是否购买域名并启动备案；③ 演示账号口令的分发与轮换周期。
