# 网页功能测试技术优化方案

> 状态：待产品确认后实施 ｜ 日期：2026-09-04 ｜ 来源：用户在 `http://127.0.0.1:8080` 的功能测试
> 
> 本文是对测试问题的技术拆解，不改变既有合规、数据分层、人工审批和状态机契约。测试期仍仅允许 `manual_trigger`；"联网"仅指每次由人工点击发起的合规公开页面采集，不是定时或全网采集。

## 1. 目标体验与边界

用户完成一条业务主线的方式应为：

```text
人工发起联网搜索 -> 返回可核验的公告候选列表 -> 人工选择一个项目深入
-> 导入公告详情原文并建立项目 -> 上传完整招标文件 -> 解析出可读的招标要求
-> 人工复核不确定的解析项 -> 规则匹配企业资料 -> 对缺失项定向补录 -> 人工审批
```

- 公告搜索页只呈现公告页面可确证的事实和原始链接，不能显示"值得投"等结论。
- 联网搜索只接收关键词、地区和已启用数据源等采集范围；种类、规模是返回公告候选后的列表内筛选条件，不得作为搜索前的采集过滤条件。
- 搜索候选不等于已入库项目；只有人工选择后才抓取详情、固化原文、建立 `project_id`。
- 完整招标文件上传后，解析页应先展示"招标要求"，而不是 Material ID、SHA-256 或企业证据编号。技术标识仅在"原文与审计"折叠区显示。
- 企业证据只能在匹配和补录阶段显示，且每个结论都必须回链 `clause_ref` 与 `evidence_ref`。
- 缺失数据默认阻断；补录不会自动使项目可投，仍须核验、重算和负责人审批。

## 2. 现状诊断

| 测试现象 | 已定位原因 | 影响 |
|---|---|---|
| 搜索后显示“测试期 manual_trigger 不联网采集，返回 0 条” | 页面在 `done.items` 为空时硬编码了过期空态；后端已有真实 `announcement.search` 执行器，但前端未区分“零命中、限频、robots 拒绝、接口/worker 不可用”。 | 用户误以为联网搜索未实现，无法判断结果是否真实。 |
| 结构化推送初始加载失败或无内容 | 页面依赖登录态和固定 `ND-2025` 项目，未登录时只显示权限失败；搜索候选也未提供“选择深入/导入详情”的可操作入口。 | 搜索、选择项目和上传未形成闭环。 |
| 点击上传区域后似乎选择成功，但不能打开或上传 | 前端隐藏原生 file input，并只接受 `.pdf,.docx`；未显式展示选择失败、格式不支持、文件大小、登录失效和上传网络错误。固定幂等键还会使不同重试被误当成同一请求。 | 用户不知道文件是否已真正选中、是否能上传、失败如何解决。 |
| 未选文件点击解析后，后续又出现 27 项复核 | 解析执行器的设计是“产出全部规则/主卡候选后进入 `manual_review`”；界面把复核数量当成异常提示，未解释候选的类别、业务含义、来源条款和处理后果。 | 用户把正常的“解析确认”误解为需要补录 27 项材料。 |
| 人工补录页不知道补什么 | 同一页混合了“解析候选复核”和“匹配缺证处置”；解析候选只显示内部编号、页码、截断原文，补录按钮也不携带 requirement、缺失类型、建议材料或目的。 | 无法完成定向补录，且容易把错误材料挂到项目。 |
| 无法选择 Excel | `prototype/queue.html` 的 `accept` 仅为 `.pdf,.docx`，而企业资料导入/补录并未按材料类型区分。 | 人员、业绩、资质清单等常用 Excel 资料无法导入。 |

## 3. 优化方案

### 3.1 联网搜索、结构化候选与人工选择

1. 保留 `POST /api/v1/intake/announcement/search` 的 job 化模式，前端状态拆为：提交中、执行中、命中、零命中、合规跳过、抓取失败、worker 不可用。禁止将任一状态泛化为“测试期不联网”。
2. 搜索表单仅保留关键词、地区和来源范围；移除搜索前的“种类”“规模”控件。`POST /api/v1/intake/announcement/search` 不再接收或执行这两个筛选条件，确保本次联网检索先返回完整候选集。
3. 搜索响应新增或统一为候选卡 DTO：`candidate_id`、`title`、`publish_date`、`source_name`、`source_url`、`source_category`、`region`、`project_type`、`scale`、`fact_status`、`missing_fields[]`、`import_status`。列表页没有的地区、金额、类别或规模必须显示“公告列表未提供，待详情页确认”，不能推断。
4. 候选列表顶部提供“种类”和“规模”筛选器，均在搜索完成后生效：种类可由公告标题的可审计关键词或详情页字段筛选；规模仅按详情页已证实的预算/规模字段分组。信息未提供的候选显示“规模待确认”，默认保留在列表中，并支持用户单独查看，不能因未知值被当作不匹配排除。
5. 列表内筛选采用客户端即时过滤当前搜索结果；候选很多时改为 `GET /intake/announcement/search/{job_id}/candidates?project_type=...&scale=...` 的服务端分页筛选。该接口只过滤已保存的候选，不触发新的外网请求、不改变原始搜索任务和候选事实。
6. 每张候选卡提供“查看公告原页”和“选择深入”两个动作。“选择深入”调用 `POST /intake/announcement/candidates/{candidate_id}/import`，轮询完成后返回新 `project_id`，并携带该 ID 跳转解析页。不能继续使用固定 `ND-2025`。
7. 搜索页默认展示最近搜索任务及其逐源摘要，支持重新打开候选，不把候选只放在临时 DOM 中。数据库可复用现有 `announcement_candidates`；需增加任务查询或按操作者/时间的列表接口。
8. 搜索前执行健康检查：API、数据库、worker、已启用数据源。worker 未运行时显示“任务已创建，等待处理服务”，并给出任务 ID，不假装零结果。

### 3.2 项目上下文和完整招标文件上传

1. 将 `project_id` 与 `candidate_id` 写入 URL 参数或受控前端状态，例如 `import.html?project_id=PJ-...`；解析页先校验项目来自人工选择，未选择时只显示“返回搜索结果选择项目”，禁用上传。
2. 上传区改为可访问的原生 `<input type=file>` 加可见按钮和拖放区；选择后显示文件名、扩展名、大小、最后修改时间和“待上传”状态。选择取消、格式错误、超限、空文件、网络失败都应有独立提示。
3. 招标文件上传类型固定为 `.pdf,.docx`，前后端均进行后缀、MIME、魔数、空文件和上限校验；`.gef/.etb` 明确提示“不支持且不会绕过加密保护”。
4. 每次点击上传生成新的客户端 `Idempotency-Key`；只有“同一个文件、同一项目、同一用户的重复提交”复用该 key。上传成功后显示可读名称和版本，SHA-256 移入审计详情。
5. 把 API 连接状态显示为可诊断信息：未登录、401、403、API 不可达、跨域错误、worker 未运行分别说明，避免把真实失败误写成“已选择招标文件正文”。

### 3.3 解析结果：以招标要求为中心

解析完成不直接跳转“人工补录”。增加“解析结果”页签，按业务语言分组呈现：

| 分组 | 每项最少展示字段 | 示例目的 |
|---|---|---|
| 项目基本信息 | 项目名称、招标人、项目地点、限价、截止时间 | 让用户确认解析对象正确。 |
| 资格与资质 | 要求名称、是否硬性、具体等级/范围/有效期 | 识别企业必须具备的资质。 |
| 项目经理与人员 | 岗位、专业/等级、数量、B/C 证、社保/在施限制 | 确认人力资源要求。 |
| 业绩、财务、信用 | 时间窗口、金额/数量、证明材料、评分/硬性属性 | 判断需准备哪些证据。 |
| 场地、设备和其他资源 | 资源类型、数量/面积/能力、是否允许联合体 | 展示项目实际资源约束。 |
| 投标动作与风险条款 | 报名、保证金、递交、开标、废标条件 | 提醒人工完成时限动作。 |

每条要求卡必须显示：可读标题、要求值、`hard/scored/action`、原文摘录、条款号、页码、解析置信状态、缺失或歧义原因、原文定位链接。内部 `requirement_id`、`material_id` 和 hash 仅作为“审计信息”折叠展示。

### 3.4 将“解析复核”与“材料补录”拆成两个任务

1. 解析复核队列只处理“系统从招标文件读到了什么”。对每项提供：确认无误、编辑后确认、标记无法确认；标记无法确认时必须选择原因（扫描不清、条款冲突、未识别、需业务解释等），这不是上传企业材料。
2. 仅对低置信、冲突、缺页、必填字段缺失的候选进入复核队列；高置信且规则完整的候选可批量确认，但必须保留抽样复核和审计记录。不得以“27 项”这种总数替代待办说明。
3. 匹配完成后才生成“材料补录队列”。每个待办绑定 `requirement_id`、条款、项目、缺失字段、阻断原因、建议证据类型、材料归属（企业长期资料/本项目投标文件/人工说明）、负责角色、截止时间和补录后的下一步。
4. “补录材料”按钮把上述上下文带入表单，禁止使用无语义的默认 `MAT-ND-SUPPLEMENT`。上传成功后材料需先进入 `pending_verification`，数据管理员核验后才可重算。

### 3.5 支持 Excel，但按资料类型受控导入

1. 将上传入口分为“招标文件”和“补录证据/企业资料”，不能用同一 accept 规则。补录支持 `.pdf,.docx,.xlsx,.xls,.csv`；图片型证据可在 OCR 方案确认后支持 `.jpg,.jpeg,.png`。
2. Excel 不应作为“不可见附件”直接入库：先选择资料类型（资质、业绩、人员、项目经理、财务/信用、项目专用证明），上传后提供工作表、表头、行数预览和字段映射；无法识别的列标为待人工确认。
3. 服务端使用内容嗅探及安全解析，拒绝加密、损坏、超大、公式外链/宏风险文件；保留原文件不可变版本，结构化记录与原文件页签/行号回链。
4. 对单份证明（PDF/DOCX）走现有 Material/OCR/核验链；对台账（Excel）走企业资料导入服务。两者都必须记录数据责任人、来源、有效期、核验状态和关联的缺失要求。

## 4. 接口和数据调整

| 范围 | 调整 |
|---|---|
| 搜索 | 搜索请求只传关键词、地区和来源；扩充候选 DTO 的 `project_type`/`scale` 事实字段；增加历史搜索、候选列表和对既有候选的种类/规模筛选接口；候选确认导入成功后返回 `project_id`。 |
| 项目 | `GET /projects/{project_id}` 返回项目可读状态、选中的公告、招标文件和解析摘要，不绑定演示项目。 |
| 解析 | 增加解析结果聚合接口，如 `GET /parse/projects/{project_id}/requirements`，返回业务字段、引用和复核状态；复核接口支持 `revised` 及结构化原因。 |
| 补录队列 | 队列 DTO 增加 `missing_field`、`reason`、`purpose`、`recommended_material_types`、`owner_role`、`due_at`、`requirement_id`、`clause_ref`。 |
| 材料 | 创建补录材料时传 `requirement_ids[]`、`material_subtype`、`intake_mode`；Excel 导入新增受控预览/映射/确认接口，不能混入招标文件解析接口。 |
| 可观测性 | 搜索、上传、解析、复核、补录、核验、重算均返回 `request_id`/`job_id`，前端可查看人类可读的状态和下一步。 |

## 5. 实施顺序与验收

### P0：恢复可验证主线

1. 修正搜索页空态、搜索任务状态和候选卡“选择深入”动作；将种类、规模从搜索前表单迁移到搜索结果列表的筛选栏。
2. 去除固定 `ND-2025` 依赖，打通 candidate -> project -> import 的项目上下文。
3. 修正上传控件、格式/错误反馈和幂等键生成；验证 PDF/DOCX 从选择到入库、解析任务、状态回写的全程可见。
4. 将解析结果页面改成招标要求分组；解析复核和材料补录分流。

验收：人工搜索一次已启用 L1 源，结果如实呈现命中或原因；无需重新联网请求即可在结果中按种类、规模筛选，且“规模待确认”候选不会被默认隐藏；选中一条候选后能上传一份 PDF/DOCX；用户能在不看内部编码的情况下说清“本项目需要什么资质、人员、业绩和动作”。

### P1：让补录可执行

1. 为处置队列补齐缺什么、为何缺、补来做什么、由谁补、关联哪条款的字段。
2. 增加资料类型选择、定向关联 requirement、数据管理员核验和重算结果回写。
3. 支持 Excel 的安全预览、映射和企业资料导入；完成 PDF/DOCX/Excel 三类正反例测试。

验收：任意一条 `blocked_missing_data` 能从队列跳转到预填补录表单，上传和核验后重算；Excel 资料能预览、映射并保留来源行回链。

### P2：可靠性与运营

1. 搜索/解析 worker 健康检查、任务失败重试和状态恢复。
2. 搜索历史、项目列表、原文/版本/审计信息的可追溯展示。
3. 解析质量指标：字段引用完整率、人工驳回率、低置信率、从上传到可复核的耗时；对每个启用源建立真实样本回归集。

## 6. 必测场景

| 场景 | 预期 |
|---|---|
| 搜索命中 / 零命中 / robots 拒绝 / 限频 / worker 未运行 | 五种状态有不同文案、原因和下一步；不出现“测试期不联网”的错误结论。 |
| 结果内种类/规模筛选 | 不发起二次外网抓取；种类、已确认规模筛选正确；未知规模默认保留并可单独筛选。 |
| 未登录和越权 | 操作前提示登录或权限不足，不产生任务和材料。 |
| 招标文件：PDF、DOCX、空文件、XLSX、GEF/ETB | 前两者可上传解析；空/Excel/加密固化格式被招标文件入口明确拒绝。 |
| 补录：PDF、DOCX、XLSX、XLS、CSV、损坏/含宏文件 | 合法格式按资料类型预览入库；风险文件被拒绝且无持久化残留。 |
| 解析结果 | 每条资格/人员/资源要求都能显示要求值、条款、页码、原文摘录和复核状态。 |
| 复核和补录 | 驳回解析候选不会伪装成补录待办；缺证待办可解释、可定向上传、核验前不能重算。 |

## 7. 约束与决策

- 不启用 `scheduled`，不绕过 robots、登录、付费或技术保护；新数据源仍须纳入合规清单并经过既定审核。
- 不把公告列表的标题关键词、解析模型置信度或搜索排序作为投标判断或准入分数。
- 上传、Excel 预览和外部模型调用须遵守企业私有资料隔离；企业资料不得发送给外部模型。
- 本文涉及新的补录队列字段、Excel 导入契约和解析结果 API，实施前须在相应 F020/F021/F022/F023 规格中冻结；若变更已冻结字段或状态机，先登记 ADR/规格变更再编码。
