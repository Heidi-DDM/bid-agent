# 开发执行与验收清单

> 版本：v1.0 ｜ 日期：2026-09-02 ｜ 适用交付：D1 农大演示薄切片、D2 受限生产试用、D3 规模化验证
>
> 本清单将“已实现、可演示、客户可用”分开管理。任何未完成项必须记录状态、责任人、证据和阻塞原因，不得以离线脚本或静态原型替代运行时验收。

## 1. 开工前置确认

- [ ] 经营部确认三类要求、评分项分值、硬性否决项和“内部满分准入”口径。
- [ ] 确认投标负责人、审批人、人工豁免授权人及豁免有效期规则。
- [ ] 确认企业资料字段责任人、核验频率和 `pending_verification -> active` 流程。
- [ ] 完成农大资料的真实/脱敏使用授权；个人信息处理方式经法务确认。
- [ ] 明确 D1 仅 `manual_trigger`，不启用 `scheduled`；数据源合规清单取得法务签字后才允许 D2/D3 采集扩展。
- [ ] 准备可复现环境：PostgreSQL/pgvector、对象存储、OCR、embedding、模型出域配置和备份目标。
- [ ] 固定测试样本：农大招标文件版本、20 条规则金标准、最小企业资料集、缺证 NQ-H-007 和权限负例。

## 2. D1 技术执行任务（R021-R024 + R012）

### 2.1 R021 招标材料入库与解析

- [ ] 实现公告/单条 URL/文件的 `manual_trigger` 入库，robots、限频、UA 和 raw 不可变约束可测试。
- [ ] 实现 PDF/DOCX 文本抽取、扫描件路由、页码与 hash 保留、失败重试和人工复核队列。
- [ ] 实现 `parse.tender_document` worker：条款、资格、评分、时间线、废标候选 JSON，逐项回链 clause/page。
- [ ] 实现规则候选复核 API；人工确认后才写入 RuleSet/Requirement，历史版本不可覆盖。
- [ ] 解析完成后自动创建 L2 索引并触发一次匹配；重复任务幂等。

### 2.2 R022 企业资料导入与核验

- [ ] 导入资质、业绩、建造师、职称、岗位证书和证据文件；统一版本、hash、有效期、责任人和 `verified_at`。
- [ ] 接入 OCR Document Router；低置信度、损坏 PDF 和字段缺失进入人工复核，不静默入库。
- [ ] 补齐项目经理 B 证/注册编号等字段口径；对 1145/1181 人数差异形成数据核验记录。
- [ ] 提供核验队列、批量确认、驳回和重导入；未核验资料不得参与准入匹配。
- [ ] 企业资料 active 版本完成 L3 索引，支持 `as_of`、项目和权限过滤。

### 2.3 R023 匹配与准入服务

- [ ] 将 RuleSet/Requirement 快照、企业资料快照和 `as_of` 写入 MatchRun。
- [ ] RAG 仅提供候选证据；金额、日期、等级、有效期由结构化字段和确定性规则核验。
- [ ] 输出 satisfied/failed/unverifiable，并将缺失映射为 `blocked_missing_data`，硬性失败映射为 `blocked_hard_requirement`。
- [ ] 提供风险/缺项聚合 API、证据引用、重算幂等和结果版本对比。
- [ ] 禁止向量分数、LLM 置信度直接进入准入公式。

## 3. 证据化验收清单

### D1 演示退出条件

- [ ] 农大单项目从手动入库到审批全流程成功，且重复投递/重算幂等。
- [ ] 20/20 条规则均有执行记录；与人工金标准逐条对照并记录差异。
- [ ] 每条结论均有 clause 引用和企业 evidence 引用；引用完整率 100%。
- [ ] NQ-H-007 等缺证项保持 `unverifiable/blocked_missing_data`，不得推断满足。
- [ ] 权限负例跨项目访问为 403，公开层与企业层无泄漏。
- [ ] 解析失败、OCR 低置信度、模型不可用均进入可解释复核/重试状态。
- [ ] 演示环境、样本和限制清单交付，明确“不支持批量采集、不自动投标、不代表生产安全”。

### D2 受限生产退出条件

- [ ] 正式认证、角色权限、密钥管理、HTTPS 和对象存储 ACL 完成部署验证。
- [ ] 数据库与对象存储成对备份；完成恢复演练并记录 RTO/RPO。
- [ ] `/healthz`、`/readyz`、worker、任务失败重试、审计和告警在部署环境通过。
- [ ] R025 黄金查询集至少 50 条、双人标注；L2/L3 Recall 达到规格阈值 0.90。
- [ ] 至少 200 个数字/日期/等级/有效期字段完成 exact-match 验证，准确率达到 0.95。
- [ ] 客户完成用户验收并确认评分规则、资料责任人、审批人和限制边界。

### D3 规模化退出条件

- [ ] 至少 3 个真实/脱敏项目完成全流程，形成耗时、准确率、修改率、漏项发现率报告。
- [ ] 指定来源采集通过合规清单、限频、robots、失败熔断和归档验收。
- [ ] scheduled 仅在 P0 验收和法务签字后启用，并可回滚到 manual_trigger。
