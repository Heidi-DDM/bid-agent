# F005-项目主卡事实子卡与字段溯源

- **需求来源**：R005 ｜ **状态**：draft（Iteration 1 冻结）
- **关联**：旧 PRD §六、复用方案 §四（4.1-4.4）、F004、F008

## 1. 背景与目标

- **背景**：既有"一项目一主卡 + 事实子卡 + 字段级原文溯源"模型（旧 PRD §6.1/§6.2、事实卡模板）已用于公告；需承接招标文件解析产物，并将 advantage 子卡从占位升级为正式匹配载体。
- **目标**：冻结主卡/子卡字段与溯源规范，支撑 F008 匹配矩阵与满分准入。

## 2. 非目标

- 不改变既有公告事实卡语义（basic/time/qualification/scoring/amount/compliance/requirement/checklist 保留）；
- 不新增分析断语字段。

## 3. 用户角色与端到端步骤

| 角色 | 步骤 |
|---|---|
| 投标专员 | 查看主卡/子卡与字段溯源 → 人工修正 → 确认 |
| 数据管理员 | 在 advantage 子卡关联企业资料 |
| 经营负责人 | 查看匹配矩阵（F008 产物） |

端到端步骤：解析产物 → 主卡聚合 → 子卡拆分 → 字段级溯源核验 → 门禁通过 → 匹配（F008）。

## 4. 数据对象

### 4.1 项目主卡（沿用旧 PRD §6.1 字段 + 本期增量）

- 既有字段：card_id / project_id / project_name / tender_no / tenderee / agency / region / project_type / budget_amount / ceiling_price / bid_bond_amount / deadline_signup / deadline_bid / open_date / qualification_requirements[] / scoring_rules[] / source_links[] / confidence / status（active/closed/awarded）。
- 本期增量（Iteration 1 冻结，回链 ADR-001）：
  - `tender_document_ref`：招标文件 raw 引用（一个项目可多份，版本不覆盖）；
  - `company_advantage`：由占位升级为匹配矩阵引用（每条匹配结论回链 clause + evidence）；
  - `admission_status`：准入状态（ADR-001 §2.2 状态机），由匹配/审批层维护。

### 4.2 事实子卡

| 子卡类型 | key | 内容 |
|---|---|---|
| 基本信息 | basic | 主卡之外补充信息 |
| 时间线 | time | 报名/答疑/投标/开标/保证金（deadline_bid 必填） |
| 资格要求 | qualification | 资质/人员/业绩/财务/信用/联合体/审查方式 |
| 评分规则 | scoring | 评审办法/商务/技术/资信权重/废标条款 |
| 金额限价 | amount | 预算/限价/保证金/履约保证金 |
| 合规约束 | compliance | 暗标/CA/递交方式/原件备查 |
| 清单式要求 | requirement | 资格/废标清单，逐条引用条款 |
| 投标动作清单 | checklist | 报名/CA/保证金/递交/开标 |
| 公司投标优势 | advantage | 匹配矩阵载体（本期正式启用，引用企业私有库） |

### 4.3 字段级溯源规范

每个非空字段必须携带：`clause`（招标条款号，可空=公告级）+ `source_link` + `assertion`（原文摘录，逐字）+ `confidence`（来源映射：官方=confirmed/第三方=high/转载=medium）。

## 5. 输入/输出与证据要求

- 输入：公告/招标文件解析产物（F004）。
- 输出：主卡 + 子卡 + 溯源引用。
- 证据要求：字段值可回溯到原文；无原文支撑的字段只能为"待补/待核实"。

## 6. 业务规则

1. 一项目一主卡；子卡引用主卡 card_id；多公告按 project_id 聚合，不覆盖历史版本。
2. 纯事实红线：禁止"值得投/有倾向/中标率"等断语（子卡与主卡均适用）。
3. advantage 子卡只引用企业私有库（F006/F007），不引用公开公告；缺失资料输出"不可判定/待补材料"。
4. 主卡/子卡字段 key 变更须走文档变更流程（Iteration 1 后冻结）。

## 7. 失败/空态/异常状态

- 字段缺失：标"待补"；关键字段缺失影响准入（F008 阻断）。
- 多源冲突：保留多源记录（L3 合并），不覆盖。
- 权限不足：查看企业私有匹配明细受限（F003 权限矩阵）。

## 8. API 目标态契约

```text
GET  /api/v1/projects/{project_id}                # 主卡+子卡聚合
GET  /api/v1/projects/{project_id}/cards          # 子卡列表
GET  /api/v1/cards/{card_id}/field-traces         # 字段级溯源
POST /api/v1/cards/{card_id}/manual-fix           # 投标专员人工修正（留痕）
```

## 9. 权限、数据隔离、审计和合规

- 公开事实：public_read；advantage 子卡明细：enterprise_read / restricted。
- 人工修正必须留痕（谁、何时、改了什么、依据）。

## 10. 验收标准与测试计划

- 验收：①主卡/子卡字段与溯源规范冻结；②真实样例（≥1 公告 + 1 招标文件）可生成完整主卡/子卡；③字段级溯源可查；④无分析断语。
- 测试计划：溯源完整性检查（逐字段）、缺失标记检查、人工修正留痕用例。
