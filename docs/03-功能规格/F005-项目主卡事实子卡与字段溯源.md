# F005-项目主卡事实子卡与字段溯源

- **需求来源**：R005 ｜ **状态**：定稿 v1.4（Iteration 1 冻结）
- **关联**：旧 PRD §六、复用方案 §四（4.1-4.4）、F004、F008、`templates/事实卡模板.md`

## 1. 背景与目标

- **背景**：既有"一项目一主卡 + 事实子卡 + 字段级原文溯源"模型（旧 PRD §6.1/§6.2、事实卡模板）已用于公告；需承接招标文件解析产物，并将 advantage 子卡从占位升级为正式匹配载体。
- **目标**：冻结主卡/子卡字段与溯源规范，支撑 F008 匹配矩阵与满分准入。
- **解析对象（2026-08-26 R005 定稿）**：公告（URL/粘贴正文）与招标文件 **docx/pdf**。电子交易平台固化格式（.gef/.etb 等加密固化文件）为不支持格式 → 走 F004 §7 人工复核路径，不解析、不绕过保护。

## 2. 非目标

- 不改变既有公告事实卡语义（basic/time/qualification/scoring/amount/compliance/requirement/checklist 保留）；
- 不新增分析断语字段；
- 不解析加密固化格式（.gef/.etb）与图片型 PDF（扫描件）；不做投标文件入库。

## 3. 用户角色与端到端步骤

| 角色 | 步骤 |
|---|---|
| 投标专员 | 查看主卡/子卡与字段溯源 → 人工修正 → 确认 |
| 数据管理员 | 在 advantage 子卡关联企业资料 |
| 经营负责人 | 查看匹配矩阵（F008 产物） |

端到端步骤：解析产物 → 主卡聚合 → 子卡拆分 → 字段级溯源核验 → 门禁通过 → 匹配（F008）。

#### 4.2.1 评分项分类与打分边界（2026-08-26 R005 收尾定稿）

scoring 子卡中每个评分项必须登记 `score_nature`（objective/subjective），打分边界如下：

| 分类 | key | 定义 | 处置 |
|---|---|---|---|
| 客观打分项 | `objective` | 有明确量化公式或可查证证据的评分项：投标报价（公式）、类似业绩（数量/金额）、人员证书（等级/数量）、财务指标、工期承诺等 | **必须无遗漏提取**（评分项/分值/评分标准/公式逐项登记）；匹配层按规则自动计分（F008），证据缺失 → 待补/待核实，不编造 |
| 主观打分项 | `subjective` | 需评标委员会按评分标准主观评分的项：施工组织设计/技术方案/答辩/暗标质量等 | 提取评分项+分值结构并标注“待内部质量评审”，**系统不自动计分**；内部评审只记录通过/未通过及依据，不得回填或宣称评标委员会分数（F008） |

**打分边界规则**：

1. **客观项无遗漏**：评分细则中全部客观项必须逐项提取，缺一项即视为解析不完整 → 人工复核（与 F008 §6.3 一致），不得静默跳过；
2. **主观项不自动计分**：系统仅登记结构与分值，输出“待内部质量评审”，不得以任何默认值/推断值替代，也不得把内部意见写成评标委员会分数；
3. **不自动报价**：报价得分公式按客观项提取，但报价金额由投标编制人工输入，系统不生成报价（回链 ADR-001）；
4. 客观/主观分类由解析规则判定，投标专员可人工修正（留痕，走 F005 §8 manual-fix）。

### 4.3 字段级溯源规范

每个非空字段必须携带：`clause`（招标条款号，可空=公告级）+ `source_link` + `assertion`（原文摘录，逐字）+ `confidence`（来源映射：官方=confirmed/第三方=high/转载=medium）。

### 4.4 解析产品类型约束（2026-08-26 R005 定稿）

| 格式 | 是否解析 | 处置 |
|---|---|---|
| 公告（URL/粘贴正文） | ✅ | 既有公告链路 |
| 招标文件 .pdf（文本型） | ✅ | pdftotext 等提取 → 主卡/子卡 |
| 招标文件 .docx | ✅ | 解压提取 document.xml → 主卡/子卡 |
| 招标文件 .doc | 部分 | 文本提取（textutil），版式兼容性有限 → 失败走人工复核 |
| 加密固化 .gef/.etb/.bde | ❌ | 加密保护格式，不解析、不绕过 → 人工复核（F004 §7） |
| 图片型 PDF（扫描件） | ⚠️ | **R017（Iteration 2）引入 OCR 通道**：Document Router 分流 → OCR → 结构化文本；保留原文 hash+置信度+页码，低置信度 → 人工复核（本表 2026-08-26 由"不支持"升级，见变更记录） |
| 投标文件（企业私有） | ❌ | 不入公开情报库；仅版式开发测试可用（数据隔离） |

## 5. 输入/输出与证据要求

- 输入：公告/招标文件解析产物（F004），支持 docx/pdf。
- 输出：主卡 + 子卡 + 溯源引用。
- 证据要求：字段值可回溯到原文；无原文支撑的字段只能为"待补/待核实"。

## 6. 业务规则

1. 一项目一主卡；子卡引用主卡 card_id；多公告按 project_id 聚合，不覆盖历史版本。
2. 纯事实红线：禁止"值得投/有倾向/中标率"等断语（子卡与主卡均适用）。
3. advantage 子卡只引用企业私有库（F006/F007），不引用公开公告；缺失资料输出"不可判定/待补材料"。
4. 主卡/子卡字段 key 变更须走文档变更流程（Iteration 1 后冻结）。
5. 招标文件与公告同项目时合并到同一主卡（多 raw 版本不覆盖）；解析失败 → 人工复核。
6. 打分边界（§4.2.1）：scoring 子卡评分项必须登记 `score_nature`；客观项无遗漏提取并自动计分（证据化），主观项只登记结构、不自动计分、交人工判定；不自动报价。

## 7. 失败/空态/异常状态

- 字段缺失：标"待补"；关键字段缺失影响准入（F008 阻断）。
- 多源冲突：保留多源记录（L3 合并），不覆盖。
- 权限不足：查看企业私有匹配明细受限（F003 权限矩阵）。
- 加密固化格式（.gef/.etb）：不支持，人工复核，不绕过保护。
- 图片型 PDF（扫描件）：R017 OCR 通道（Document Router），低置信度 → 人工复核。

> 该样例为**解析链路可行性验证**，未入库、未提交 Git（企业私有素材）。真实主卡/子卡生成在 Iteration 2 原型落地。

**评分细则演练（2026-08-26 双项目，验证 §4.2.1 打分边界）**：

| 项目 | 评分构成 | 客观项（自动计分） | 主观项（人工判定） |
|---|---|---|---|
| 博野县高标准农田 | 施工组织设计 55 + 项目管理机构 5 + 投标报价 40（100 分制） | 投标报价 40（按评分公式计算） | 施工组织设计 55（暗标评审）；项目管理机构 5（按评分标准逐条分类，人员配置量化部分客观、合理性评审部分主观，投标专员可修正） |
| 邢台市排水管网 | 综合评估法（招标文件第三章） | 待完整解析评分细则后逐项分类登记 | 同左 |

**演练结论**：报价类客观项可解析公式并自动计分；施组类主观项系统只登记结构与分值、不评分 → 与 §4.2.1 打分边界一致；客观项提取不全时走人工复核。
