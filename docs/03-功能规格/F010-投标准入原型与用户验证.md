- 主旅程数据 = 农大脱敏案例（河北农业大学东校区研究生宿舍建设项目施工，事后验证样本）：20 条规则（hard 12/scored 4/action 4，与 `scripts/matching/golden_requirements_nongda.json` 一致）+ 匹配矩阵（与 `验证受限材料/农大/nongda_match_result.json` 一致）+ 审批记录（与 `approval_demo_result.json` 一致；待审批条目为补齐材料后构造口径，仅演示审批流）。
- 主流程已按用户反馈收敛为“联网搜索与结构化推送 → 人工选择深入并上传完整招标文件 → 招标文件解析 → 自动读取已解析企业资料并匹配 → 风险/缺失展示 → 人工补录 → 人工审核”；企业资料页仅作为数据管理员维护的后台状态页，不属于项目主流程。右上角角色切换继续模拟四层权限（§9）。
- 使用说明与数据口径见 `prototype/README.md`。

## 1. 背景与目标

- **背景**：在冻结契约与开发薄切片之前，需要先用真实/脱敏案例做可点击原型，让投标专员/经营负责人验证流程与评分规则。
- **目标**：定义原型页面、交互、异常态与验证方法。**本规格只定义原型，不开发完整前后端。**

## 2. 非目标

- 不开发真实前后端；不实现真实计算引擎；不接入真实数据库；不做权限系统实现（用假数据模拟）。

## 3. 用户角色与端到端步骤

| 角色 | 原型中动作 |
|---|---|
| 投标专员 | 搜索/查看结构化推送 → 选择深入项目并上传完整招标文件 → 查看解析与自动匹配 → 处理风险/缺失 → 发起人工审核 |
| 数据管理员 | 在原型中模拟资料导入与核验 |
| 经营负责人 | 查看人工补录后的结果 → 审批/驳回/豁免 |
| 法务 | 查看合规说明页 |

端到端原型流程：联网搜索与结构化推送 → 人工选择深入项目 → 上传完整招标文件 → 招标文件解析 → 自动匹配已解析企业资料 → 展示风险项与缺失项 → 人工补录 → 人工审核/审计。

## 4. 原型页面清单（主流程 7 类 + 异常态）

| # | 页面 | 关键元素 |
|---|---|---|
| 1 | 搜索与结构化推送 | 联网搜索公告并生成结构化事实卡；测试期手动触发 |
| 2 | 选择与解析 | 从结构化推送选择项目，上传完整招标文件；原文查看（不可变）、版本列表、解析状态（parsed/partial/failed） |
| 3 | 解析与自动匹配 | 三类要求 tab（hard/scored/action）；条款号、原文摘录、自动匹配状态、缺失项和证据抽屉 |
| 4 | 风险与缺失 | 展示自动匹配后的风险、缺失、阻断状态、逐条证据和处理建议；不重复选择资料或触发第二次匹配 |
| 5 | 字段级证据抽屉 | 点击任意匹配结果 → 抽屉展示招标条款引用 + 企业证据引用 + 原文摘录 |
| 6 | 人工补录 | 针对缺失项上传材料、登记核验和人工复核，完成后重新执行匹配 |
| 7 | 人工审核/审计 | pending_bid_approval 列表；经营负责人审批/驳回/豁免并留痕 |
| 8 | 异常态 | 空态（无资料/无经理）、资料过期、解析失败、权限不足、无合格项目经理 |

## 5. 数据与证据要求（原型用）

- 使用脱敏真实案例（候选：康保储能EPC、广宗葫芦中学、阜平县高铁片区管网项目）。
- 每个自动匹配结果展示：硬性满足数、风险项、缺失项、阻断状态、招标条款引用、企业证据引用、项目经理自动筛选结果（主推荐/备选）；评分信息仅作为规则结果字段展示，不触发第二次匹配。

## 6. 业务规则（原型须体现）

1. 满分 ≠ 自动投标：人工审核页明确最终决定由企业负责人作出。
2. 数据缺失默认阻断：原型中缺失项必须展示"待补/待核实/不可判定"，不得显示满足。
3. 硬性缺项一票否决：展示阻断原因与条款引用。
4. 无合格项目经理：明确提示，不计入满分。

## 7. 失败/空态/异常状态（原型必须覆盖）

- 空态：资料库为空 → 匹配页显示"不可判定/待补材料"。
- 资料过期：显示 expired 徽标，不计分。
- 解析失败：显示 manual_review，可跳转人工复核。
- 权限不足：非审批人访问审批页 → 403 模拟页。
- 无合格项目经理：风险与缺失页显示"无合格可用项目经理"，准入判定为阻断。

## 8. API 目标态契约（原型为后续冻结输入）

- 原型交互映射到 F004-F009 的目标态 API（模拟数据），供 Iteration 3 冻结最终契约。

## 9. 权限、数据隔离、审计和合规（原型体现）

- 原型中审批层数据仅审批角色可见（模拟登录）；脱敏展示项目经理信息；审计时间线展示。

## 10. 验收标准与测试计划

- 验收：①首页可联网搜索并生成结构化推送；②人工选择后必须上传完整招标文件；③解析完成自动匹配一次；④风险/缺失可进入人工补录并提交人工审核；⑤5 类异常态可演示；⑥用户验证 ≥3 场（投标专员/经营负责人/数据管理员）并记录反馈。
- 测试计划：每页面走查清单；用户验证脚本（流程确认、评分规则确认、字段确认、队列确认）；反馈登记表。
