## 1. 背景与目标

- **背景**：在冻结契约与开发薄切片之前，需要先用真实/脱敏案例做可点击原型，让投标专员/经营负责人验证流程与评分规则。
- **目标**：定义原型页面、交互、异常态与验证方法。**本规格只定义原型，不开发完整前后端。**

## 2. 非目标

- 不开发真实前后端；不实现真实计算引擎；不接入真实数据库；不做权限系统实现（用假数据模拟）。

## 3. 用户角色与端到端步骤

| 角色 | 原型中动作 |
|---|---|
| 投标专员 | 新建任务 → 导入公告/招标文件 → 查看要求矩阵 → 选择资料/候选经理 → 复核匹配 → 处理阻断/待补 |
| 数据管理员 | 在原型中模拟资料导入与核验 |
| 经营负责人 | 查看满分评分面板 → 审批/驳回/豁免 |
| 法务 | 查看合规说明页 |

端到端原型流程：新建投标准入任务 → 导入/查看公告与招标文件 → 招标要求矩阵 → 公司资料选择（资质/业绩/项目经理）→ 字段级证据抽屉 → 满分评分面板 → 阻断/待补/复核队列 → 待投标审批 → 审批/驳回/豁免/审计。

## 4. 原型页面清单（10 类必含）

| # | 页面 | 关键元素 |
|---|---|---|
| 1 | 新建投标准入任务 | **首页入口必须是"新建投标准入任务"**（不是"新建知识库"/"开始聊天"）；表单：项目名称/来源 URL/上传招标文件/粘贴正文 |
| 2 | 导入/查看公告和招标文件 | 原文查看（不可变）、版本列表、解析状态（parsed/partial/failed）、原文链接 |
| 3 | 招标要求矩阵 | 三类要求 tab（hard/scored/action）；条款号、原文摘录、匹配状态、缺失项 |
| 4 | 公司资料选择 | 资质/业绩/项目经理选择器；主推荐/备选标记；资料状态（active/expired/pending_verification） |
| 5 | 字段级证据抽屉 | 点击任意匹配结果 → 抽屉展示招标条款引用 + 企业证据引用 + 原文摘录 |
| 6 | 满分评分面板 | 总分、满分差距、各计分项得分/max_score、硬条件列表、动作项状态、项目经理匹配结果 |
| 7 | 阻断项/待补项/人工复核队列 | 三类队列卡片：blocked_hard_requirement / blocked_missing_data / manual_review |
| 8 | 待投标审批页 | pending_bid_approval 列表 + 准入摘要 |
| 9 | 审批/驳回/豁免/审计 | 审批通过/驳回（必填意见）/豁免表单（授权人/原因/证据/有效期）；审计时间线 |
| 10 | 异常态 | 空态（无资料/无经理）、资料过期、解析失败、权限不足、无合格项目经理 |

## 5. 数据与证据要求（原型用）

- 使用脱敏真实案例（候选：康保储能EPC、广宗葫芦中学、阜平县高铁片区管网项目）。
- 每个匹配结果展示：总分、满分差距、阻断项、待补项、招标条款引用、企业证据引用、项目经理匹配结果（主推荐/备选）。

## 6. 业务规则（原型须体现）

1. 满分 ≠ 自动投标：评分面板明确文案"满分仅进入人工审批"。
2. 数据缺失默认阻断：原型中缺失项必须展示"待补/待核实/不可判定"，不得显示满足。
3. 硬性缺项一票否决：展示阻断原因与条款引用。
4. 无合格项目经理：明确提示，不计入满分。

## 7. 失败/空态/异常状态（原型必须覆盖）

- 空态：资料库为空 → 匹配页显示"不可判定/待补材料"。
- 资料过期：显示 expired 徽标，不计分。
- 解析失败：显示 manual_review，可跳转人工复核。
- 权限不足：非审批人访问审批页 → 403 模拟页。
- 无合格项目经理：评分面板显示"无合格可用项目经理"，准入判定为阻断。

## 8. API 目标态契约（原型为后续冻结输入）

- 原型交互映射到 F004-F009 的目标态 API（模拟数据），供 Iteration 3 冻结最终契约。

## 9. 权限、数据隔离、审计和合规（原型体现）

- 原型中审批层数据仅审批角色可见（模拟登录）；脱敏展示项目经理信息；审计时间线展示。

## 10. 验收标准与测试计划

- 验收：①首页入口为"新建投标准入任务"；②10 类页面齐全；③5 类异常态可演示；④端到端流程可点击走通；⑤用户验证 ≥3 场（投标专员/经营负责人/数据管理员）并记录反馈。
- 测试计划：每页面走查清单；用户验证脚本（流程确认、评分规则确认、字段确认、队列确认）；反馈登记表。
