# F019-数据库与原文证据持久化

- **需求来源**：R019 ｜ **状态**：定稿草案 v1.0（2026-08-31）
- **关联**：F003、F004、F006-F009、F018、F025、ADR-001、ADR-002

## 1. 目标与边界

将当前 Markdown/YAML/JSON 演练对象持久化为可查询、可版本化、可恢复的数据层。业务字段仍以 F003/F006-F009 为准，本规格只规定存储实现。

非目标：不把原始企业资料提交 Git；不覆盖 raw；不在数据库中保存明文密钥；不做跨企业共享。

## 2. 逻辑分层

使用同一 PostgreSQL 实例中的独立 schema 或数据库角色：

- `public_data`：公告、招标文件、项目主卡、事实子卡及公开条款引用。
- `enterprise_data`：资质、业绩、人员、项目经理和私有证据元数据。
- `admission_data`：规则快照、匹配运行、准入结果、审批和豁免。
- `audit_data`：不可更新的审计事件。
- `knowledge_data`：F025 的分片、embedding 和检索运行记录；只保存可回链的文本片段和索引元数据，不替代 `public_data`/`enterprise_data` 事实表。

数据库角色分别只授予所需 schema 权限；匹配服务通过受控视图读取企业资料。

## 3. 核心表

| 表 | 关键字段 | 约束 |
|---|---|---|
| `materials` | material_id、material_type、owner_type、classification、permission_scope、content_hash、version、parse_status、data_owner | `(material_id,version)` 唯一；版本只增 |
| `material_versions` | material_id、version、object_uri、content_hash、imported_at | content_hash 不可更新 |
| `projects` | project_id、project_name、tender_document_ref、admission_status | 多版本材料按 project_id 挂接 |
| `field_traces` | object_id、field_key、clause、source_link、assertion、confidence、source_hash | 非空字段必须至少一条引用 |
| `evidence_files` | evidence_id、object_uri、source_hash、page_no、ocr_confidence、classification | 私有证据不可公开读取 |
| `qualifications`/`performances`/`personnel` | F006 字段集、material_id、status、verified_at、data_owner | 缺证据默认 pending_verification |
| `rule_sets`/`requirements` | rule_set_id、version、project_id、requirement_id、rule_json | 版本不可覆盖 |
| `match_runs`/`match_items` | run_id、as_of、mode、coverage、requirement_id、match_result、match_reason | 记录输入快照引用 |
| `admission_results` | result_id、run_id、四类结论、internal_admission_eligible、state | 结果为不可变快照 |
| `approvals`/`waivers` | F009 字段集、state、decided_at | 终态不可重复决策 |
| `audit_events` | actor、at、action、basis、outcome、object_ref | 仅追加，不提供 UPDATE/DELETE API |
| `analysis_jobs` | job_id、kind、status、attempts、input_ref、error_code、heartbeat_at | 幂等键唯一 |
| `knowledge_chunks` | chunk_id、knowledge_layer、material_id、material_version、content_hash、project_id、lot_id、text、location、permission_scope、verification_status、index_version | 材料版本/哈希不可更新；引用字段非空 |
| `knowledge_embeddings` | chunk_id、embedding_model、embedding_dim、embedding、created_at | `(chunk_id,embedding_model,index_version)` 唯一；使用 pgvector，扩展不可用时任务失败可解释 |
| `retrieval_runs` | retrieval_run_id、query_hash、filters、top_k、candidate_chunk_ids、index_version、created_at | 只追加；记录权限过滤和 `as_of` 快照 |

## 4. 原文和证据文件

对象路径按 `owner_type/material_id/version/sha256` 组织。上传流程为：临时目录 → SHA-256 → 格式/大小校验 → 原子移动 → 写入版本记录。数据库中的 `object_uri` 不允许指向仓库内路径。

同一材料内容重复上传返回既有版本；内容变化必须新建版本。哈希复核失败时任务阻断并产生审计事件。

## 5. 迁移、备份与恢复

1. 所有结构变更使用 Alembic，禁止手工改生产表。
2. 每次迁移先在脱敏数据库执行并运行黄金样本回归。
3. 每日数据库备份和对象存储清单必须成对保存；恢复后校验哈希和外键。
4. 备份文件沿用私有资料权限，保留期限由法务确认。

## 6. 验收与测试

- Material 15 字段、F006/F007/F008/F009 对象均可创建、查询、版本化。
- raw 内容更新请求被拒绝；新版本可查询且旧版本仍可回放。
- `public_data` 角色无法读取 `enterprise_data` 明细；审批数据仅 approver 视图可见。
- 随机修改对象文件后哈希校验失败，匹配任务不启动。
- 备份恢复后农大项目的规则、证据、匹配和审计引用完整。
- 三层知识库可按权限查询；索引重建不产生重复 chunk/embedding；检索运行可回放，且候选结果含材料版本、哈希和页码。
