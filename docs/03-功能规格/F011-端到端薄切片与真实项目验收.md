# F011-端到端薄切片与真实项目验收

- **需求来源**：R012、R013 ｜ **状态**：draft（D1/D3 交付规格，2026-09-02 工期校准）
- **关联**：ADR-001、ADR-002（状态机与知识库边界）、F004-F010、F018-F025（运行时实现规格）、`docs/02-迭代计划.md`（Iteration 4/5）

## 1. 背景与目标

- **背景**：契约冻结后，先开发一条端到端薄切片，验证最小闭环价值，再量化质量；不直接做大而全的系统。
- **目标**：先按 F018-F025 建成可重复运行的服务链路，再以河北农业大学东校区研究生宿舍建设项目施工（简称“农大”）作为唯一运行时试点，支持结构化公告推送 → 三层知识库索引 → 上传完整招标文件 → 解析 → RAG 召回候选证据 → 结构化核验与确定性匹配 → 风险/缺失 → 人工补录重算 → 人工审核；随后用 ≥3 个真实/脱敏项目验证检索召回、结构化准确性、耗时、人工修改和漏项发现率。

- **交付分档**：D1 只承诺农大单项目演示薄切片（预计 6-8 周）；D2 受限生产试用另需正式认证、部署、备份恢复、监控和客户验收（预计 10-14 周）；D3 才进行 ≥3 项目和采集调度验证。D1 不等于生产可用。

## 2. 非目标（薄切片与验证阶段均适用）

- 批量采集、定时调度（scheduled）、日报推送、全网监控、自动投标/报价/签章、完整标书、竞对非公开情报、成本测算/中标概率、未经授权私有数据接入。

## 3. 用户角色与端到端步骤

| 角色 | 步骤 |
|---|---|
| 投标专员 | 查看结构化公告推送 → 选择项目并上传完整招标文件 → 复核解析与自动匹配 → 处理风险/缺失 → 提交人工审核 |
| 数据管理员 | 提供最小资料集（脱敏）与核验 |
| 经营负责人 | 审批/驳回/豁免 |
| 验收人 | 按验收标准走查 + 记录质量指标 |

薄切片端到端：结构化公告事实卡 → L1 索引 → 上传农大招标文件/澄清版本并建立 L2 索引 → 企业资料核验并建立 L3 索引 → Document Router 与解析/模型抽取主卡、资格要求、评分规则、时间线、废标条款 → 按权限、标段、版本和 `as_of` 召回候选证据 → 结构化字段核验并自动执行一次确定性匹配 → 生成字段可溯源匹配矩阵和风险/缺失结果 → 人工补录/核验后以新证据版本重算 → 满足准入门禁后进入待投标审批 → 投标负责人审批/驳回并保留审计。博野只作为历史/回归样本，不作为本薄切片运行时试点。

## 4. 数据对象（薄切片范围）

- 复用 F003 Material、F005 主卡/子卡、F006 资质业绩、F007 ProjectManagerProfile、F008 RuleSet/Matrix、F009 ApprovalRecord/Waiver；运行时依赖 F018（环境）、F019（持久化）、F020（API/任务/RBAC）、F021（招标解析/模型）、F022（企业资料/OCR）、F023（匹配服务）、F024（结果/审批/审计）。
- 薄切片限定：单条 URL 或上传 1 份招标文件；企业资料最小集（资质 ≥1、业绩 ≥1、项目经理 ≥1）；状态机全链路（ADR-001 §2.2）。

## 5. 输入/输出与证据要求

- 输入：1 条公告/1 份招标文件 + 最小企业资料。
- 输出：匹配矩阵、风险/缺失队列、重算结果、满分判定、审批/审计记录。
- 证据要求：全链路字段级溯源（招标条款 ↔ 企业证据 ↔ 匹配结论）。

## 6. 业务规则

1. 契约优先：Iteration 3 冻结的状态机、API、权限契约是薄切片的硬约束，禁止边写边改契约（变更走文档流程）。
2. 数据缺失默认阻断；解析失败进人工复核；无自动投标路径。
3. 规则版本化：薄切片运行的项目保留当时规则版本。农大须执行当前 20 条规则源；缺失的 NQ-H-007 财务审计证据保持 `blocked_missing_data`，不得用“已中标”事实倒推满足。
4. RAG 只提供候选证据；向量相似度和模型置信度不进入准入公式，数字/日期/等级由结构化字段和确定性规则核验。
5. 质量验证指标（Iteration 5）：
   - 耗时：单项目全流程处理时长；
   - 准确性：匹配结论 vs 人工复核结论一致率；
   - 人工修改率：投标专员人工修正字段/结论占比；
   - 漏项发现率：人工复核发现但系统未识别的要求项占比。
   - 检索召回：L2 Recall@5、L3 Recall@10；数字/日期/等级字段 exact match。

## 7. 失败/空态/异常状态

| 状态 | 处置 |
|---|---|
| 解析失败 | 人工复核；计入"漏项"分析 |
| 资料不足 | 不可判定/待补，不推断 |
| 无合格项目经理 | 阻断提示 |
| 权限不足 | 拒绝访问 + 审计 |
| 接口异常 | 任务留在当前状态，不静默前进 |

## 8. API 目标态契约

- 以 Iteration 3 冻结契约（F004-F009/F025 目标态）和 F018-F025 运行时规格为准；薄切片至少实现：`announcement/search`（结构化推送）、三层索引/`knowledge/search`（候选证据）、`intake/tender-document`（完整文件上传）、`intake/{id}` 轮询、`parse/model`、`enterprise_import/OCR`、解析完成自动 `match`、`matrix`/`admission`/`queues` 只读查询、补录 `materials/{id}/verify` 后 `recalculate`、`approve/reject/waiver`、`audit` 链路。

## 9. 权限、数据隔离、审计和合规

- 同 F003/F009：分层隔离、审计完整、企业资料不入 Git。

## 10. 验收标准与测试计划

- Iteration 4 验收：①农大单条上传 + 三层知识库索引 + 最小资料端到端跑通；②20 条农大规则全量执行并保存 coverage、RuleSet、retrieval 和证据快照；③L2 Recall@5≥0.90、L3 Recall@10≥0.90、数字/日期/等级 exact match≥0.95；④权限泄漏率 0、引用完整率 100%；⑤NQ-H-007 等缺失证据保持阻断；⑥状态机迁移与 ADR-001/002 一致；⑦审计完整；⑧无自动投标。
- Iteration 4/D1 验收：①农大单条上传 + 三层知识库索引 + 最小资料端到端跑通；②20 条农大规则全量执行并保存 coverage、RuleSet、retrieval 和证据快照；③权限泄漏率 0、引用完整率 100%；④NQ-H-007 等缺失证据保持阻断；⑤状态机迁移与 ADR-001/002 一致；⑥审计完整；⑦无自动投标。Recall 和 exact-match 在黄金集建立后作为 D2 正式门禁，不得用当前参考值冒充通过。
- Iteration 5 验收：①≥3 个真实/脱敏项目；②检索、结构化、匹配和效率指标量化可复现；③权限负例和版本重放通过；④漏项/误判闭环到规则、Schema 或索引配置；⑤结论经投标专员确认。
- 测试计划：每项目走查记录（起止时间、人工修正点、漏项清单）；指标汇总表；回归用例。
