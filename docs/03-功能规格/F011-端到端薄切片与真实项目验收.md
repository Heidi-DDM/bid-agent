# F011-端到端薄切片与真实项目验收

- **需求来源**：R012、R013 ｜ **状态**：draft（Iteration 4/5 交付）
- **关联**：ADR-001（状态机）、F004-F010（全部契约）、`docs/02-迭代计划.md`（Iteration 4/5）

## 1. 背景与目标

- **背景**：契约冻结后，先开发一条端到端薄切片，验证最小闭环价值，再量化质量；不直接做大而全的系统。
- **目标**：薄切片只支持：单条 URL/上传招标文件 + 最小公司资料 + 一名或多名项目经理匹配 + 审批；随后用 ≥3 个真实/脱敏项目验证耗时、准确性、人工修改和漏项发现率。

## 2. 非目标（薄切片与验证阶段均适用）

- 批量采集、定时调度（scheduled）、日报推送、全网监控、自动投标/报价/签章、完整标书、竞对非公开情报、成本测算/中标概率、未经授权私有数据接入。

## 3. 用户角色与端到端步骤

| 角色 | 步骤 |
|---|---|
| 投标专员 | 单条 URL/上传招标文件 → 复核解析 → 选择资料与候选经理 → 复核匹配矩阵 |
| 数据管理员 | 提供最小资料集（脱敏）与核验 |
| 经营负责人 | 审批/驳回/豁免 |
| 验收人 | 按验收标准走查 + 记录质量指标 |

薄切片端到端：人工粘贴公告/上传招标文件 → 保存不可变公开原文 → 提取主卡/资格要求/评分规则/时间线/废标条款 → 导入或选择公司私有资料 → 逐项匹配企业资质、业绩与候选项目经理 → 生成字段可溯源匹配矩阵 → 计算满分准入结果 → 未满分/硬性缺项阻断进待补/待核实队列 → 满分且证据完整进入待投标审批 → 投标负责人审批/驳回并保留审计。

## 4. 数据对象（薄切片范围）

- 复用 F003 Material、F005 主卡/子卡、F006 资质业绩、F007 ProjectManagerProfile、F008 RuleSet/Matrix、F009 ApprovalRecord/Waiver。
- 薄切片限定：单条 URL 或上传 1 份招标文件；企业资料最小集（资质 ≥1、业绩 ≥1、项目经理 ≥1）；状态机全链路（ADR-001 §2.2）。

## 5. 输入/输出与证据要求

- 输入：1 条公告/1 份招标文件 + 最小企业资料。
- 输出：匹配矩阵、满分判定、审批/审计记录。
- 证据要求：全链路字段级溯源（招标条款 ↔ 企业证据 ↔ 匹配结论）。

## 6. 业务规则

1. 契约优先：Iteration 3 冻结的状态机、API、权限契约是薄切片的硬约束，禁止边写边改契约（变更走文档流程）。
2. 数据缺失默认阻断；解析失败进人工复核；无自动投标路径。
3. 规则版本化：薄切片运行的项目保留当时规则版本。
4. 质量验证指标（Iteration 5）：
   - 耗时：单项目全流程处理时长；
   - 准确性：匹配结论 vs 人工复核结论一致率；
   - 人工修改率：投标专员人工修正字段/结论占比；
   - 漏项发现率：人工复核发现但系统未识别的要求项占比。

## 7. 失败/空态/异常状态

| 状态 | 处置 |
|---|---|
| 解析失败 | 人工复核；计入"漏项"分析 |
| 资料不足 | 不可判定/待补，不推断 |
| 无合格项目经理 | 阻断提示 |
| 权限不足 | 拒绝访问 + 审计 |
| 接口异常 | 任务留在当前状态，不静默前进 |

## 8. API 目标态契约

- 以 Iteration 3 冻结契约（F004-F009 目标态）为准；薄切片至少实现：intake（URL/上传）、parse、match、admission、approve/reject/waiver、audit 链路。

## 9. 权限、数据隔离、审计和合规

- 同 F003/F009：分层隔离、审计完整、企业资料不入 Git。

## 10. 验收标准与测试计划

- Iteration 4 验收：①单条 URL/上传 + 最小资料端到端跑通；②状态机迁移与 ADR-001 一致；③审计完整；④无自动投标。
- Iteration 5 验收：①≥3 个真实/脱敏项目；②四项质量指标量化可复现；③漏项/误判闭环到规则与 Schema；④结论经投标专员确认。
- 测试计划：每项目走查记录（起止时间、人工修正点、漏项清单）；指标汇总表；回归用例。
