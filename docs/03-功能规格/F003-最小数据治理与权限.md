# F003-最小数据治理与权限

- **需求来源**：R003 ｜ **状态**：定稿（Iteration 1 已冻结契约）
- **关联**：ADR-001、F002、F006、F007、F008、`config/publish_config.yml`

## 1. 背景与目标

- **背景**：系统将同时持有公开原文与企业私有资料，必须定义最小数据治理契约（Material），保证可溯源、不可覆盖、权限隔离，支撑"满分准入"的证据化结论。
- **目标**：冻结 Material 契约：来源、归属、密级、权限、版本、有效期、解析状态；公开与企业私有数据严格隔离；所有匹配结论回链到招标条款和企业证据。

## 2. 非目标

- 不设计完整权限系统实现（Iteration 3 冻结权限契约，实现随薄切片）；不定义采集调度细节（见 F004）。**权限矩阵契约本身已在 Iteration 1 冻结（§6.2），冻结的是数据访问矩阵，不是权限系统实现。**

## 3. 用户角色与端到端步骤

| 角色 | 步骤 |
|---|---|
| 数据管理员 | 导入企业资料（资质/业绩/证照），维护有效期与责任人 |
| 投标专员 | 粘贴公告/上传招标文件；查看原文与解析状态 |
| 经营负责人 | 查看匹配结论与证据链 |
| 法务 | 审核数据来源与使用合规 |

端到端步骤：材料导入 → 校验（来源/密级/有效期/责任人）→ 存储（隔离）→ 使用（解析/匹配/结论回链）→ 过期/缺失处置。

## 4. 数据对象

### 4.1 Material（最小治理单元）

> **契约冻结（2026-08-25，R003）**：字段、枚举、必填性与 schema §13.1 逐项一致，修改走文档变更流程。

| 字段 | key | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 材料ID | `material_id` | string | 是 | 主键，如 MAT-PUB-xxx / MAT-PRV-xxx（前缀区分归属） |
| 材料类型 | `material_type` | enum | 是 | announcement / tender_document / qualification_cert / performance_record / personnel_cert / evidence_file |
| 来源类型 | `source_type` | enum | 是 | official_platform / agency / uploaded / internal / manual_entry |
| 归属类型 | `owner_type` | enum | 是 | public / enterprise |
| 密级 | `classification` | enum | 是 | public / internal / confidential |
| 权限范围 | `permission_scope` | enum | 是 | public_read / enterprise_read / restricted / approver_only |
| 原文哈希 | `content_hash` | string | 是 | SHA-256，防篡改 |
| 版本 | `version` | int | 是 | 从 1 递增，不覆盖历史 |
| 导入时间 | `imported_at` | datetime | 是 | |
| 有效期 | `valid_until` | date | 否 | 证书/证照必填 |
| 解析状态 | `parse_status` | enum | 是 | pending / parsed / partial / failed / manual_review |
| 证据文件引用 | `evidence_refs` | ref[] | 否 | 回链 evidence_file |
| 数据责任人 | `data_owner` | string | 是 | 谁负责维护/核验 |
| 最后核验时间 | `verified_at` | datetime | 否 | |
| 状态 | `status` | enum | 是 | active / expired / archived / invalid |

### 4.2 隔离与不可变约束

- 公开数据（`owner_type=public`）与企业私有数据（`owner_type=enterprise`）**严格分层存储**（不同目录/表空间 + 权限矩阵），禁止混存。
- `raw` 原文**不可覆盖**：每次导入为新增版本（`version` 递增），公告变更/澄清按 `project_id` 挂接。
- 企业证书、人员资质、业绩必须有：有效期、证据文件、数据责任人。
- 缺失字段：一律 `pending_verification` / "待补/待核实"，禁止编造。

## 5. 输入/输出与证据要求

- 输入：公开公告/招标文件（粘贴/上传/单条 URL）；企业资料（xlsx/docx/PDF，Iteration 2 起）。
- 输出：结构化 Material 记录 + 原文哈希 + 版本历史。
- 证据要求：每条匹配结论必须回链 `tender_clause_ref`（招标条款）与 `evidence_refs`（企业证据）。

## 6. 业务规则

1. Material 生命周期：import → validate → store → use → expire/archive。
2. 权限矩阵（**契约已冻结，2026-08-25，R003**；Iteration 3 冻结实现方案，目标态）：

| 数据 | 公开读取 | 企业内读取 | 受限（匹配层） | 仅审批人 |
|---|---|---|---|---|
| 公开原文/事实卡 | ✅ | ✅ | ✅ | ✅ |
| 企业资质/业绩 | — | ✅ | ✅ | ✅ |
| 项目经理个人信息 | — | 脱敏 | 匹配结果 | 明细 |
| 审批/豁免/审计 | — | — | — | ✅ |

3. 缺失/过期数据不得用于"满分"判定（见 F008）。
4. 原文哈希不一致 = 篡改风险，阻断使用。

## 7. 失败/空态/异常状态

| 状态 | 处置 |
|---|---|
| 解析失败（parse_status=failed/partial） | 人工复核，不进入匹配 |
| 权限不足 | 拒绝访问 + 审计日志 |
| 数据过期（valid_until 已过） | 标 expired，不计入满分 |
| 空态（资料未导入） | 匹配层输出"不可判定/待补材料" |
| 原文哈希不匹配 | 阻断 + 告警 |

## 8. API 目标态契约

```text
POST   /api/v1/materials                # 导入材料（公开/私有）
GET    /api/v1/materials/{id}           # 材料详情 + 版本历史
GET    /api/v1/materials/{id}/versions  # 版本列表
POST   /api/v1/materials/{id}/verify    # 数据责任人核验
PATCH  /api/v1/materials/{id}/expire    # 过期/归档
```
（Iteration 3 冻结最终契约；此处为目标态草案。）

## 9. 权限、数据隔离、审计和合规

- 权限：permission_scope 逐材料生效；审批层数据仅审批人可见。
- 隔离：公开/私有分层存储；Git 白名单（`.gitignore`）保证企业资料不入库。
- 审计：导入/核验/过期/访问记录；项目经理个人信息最小化（脱敏展示）。

## 10. 验收标准与测试计划

- 验收：①Material 字段全冻结；②公开/私有隔离可验证；③raw 不可覆盖（版本测试）；④缺失/过期处置正确。
  - **验收结果（2026-08-25，R003）**：①Material 15 字段契约冻结，枚举与 schema §13.1 逐项一致（coverage 125/125 审计通过）；②公开/私有分层隔离约束冻结（§4.2 / §13.3）；③raw 不可覆盖规则冻结（version 递增，§4.2 / §13.3）；④缺失/过期处置冻结（§4.2 / §13.4：待补/待核实、过期不计满分、解析失败人工复核、哈希不一致阻断）。
