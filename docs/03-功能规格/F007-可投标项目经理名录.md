# F007-可投标项目经理名录

- **需求来源**：R007 ｜ **状态**：定稿 v1.1（Iteration 2 冻结）
- **关联**：ADR-001 §2.3（满分定义第 4 条）、F003（Material/权限）、F006（业绩引用）、F008（匹配）

## 1. 背景与目标

- **背景**：新增业务要求第 3 条——建立可投标项目经理名录，维护资质、专业、注册证书、有效期、业绩、在建状态、可用性和证据文件，并用于招标项目匹配。
- **2026-08-27 实测盘点**（源：`3.注册建造师清单（含在施状态).xlsx`，详见 §14）：1181 行去重 1145 人；专业 11 类列勾选；等级列有值（一级/二级建造师）；**注册编号/联系电话 1181 条全为"后续补充"占位符**；无证书有效期/继续教育/安全证书字段；在施状态/在施项目名称有值。清单本身"未完善"标注 → 导入后默认 `pending_verification`。
- **测试期核验人**（2026-08-27 指定）：**项目负责人**（数据管理员/人力资源正式确认前，见 `docs/05-项目现状.md` §5 待确认 #9）。测试期所有 `verify` 动作记录该核验人 + verified_at，正式期移交。
- **目标**：定义 `ProjectManagerProfile` 数据结构、状态机与硬条件匹配规则，保证"满分可投标"中项目经理判定是证据化、可核验的；不生成不存在的经理或证书资料。

## 2. 非目标

- 不替代人事系统；不维护除招标匹配所需之外的员工信息；不采集个人非公开信息；不做"经理能力排序"之外的任何人事评价。

## 3. 用户角色与端到端步骤

| 角色 | 步骤 |
|---|---|
| 数据管理员/人事 | 录入/导入经理资料 → 上传证照证据 → 核验 → 维护在建状态与可用日期 |
| 投标专员 | 匹配时选择候选经理（主推荐/备选） |
| 经营负责人 | 查看匹配结果与证据 |

端到端步骤：导入/录入 → 证据上传 → 核验（pending_verification → active）→ 使用（F008 硬条件验证）→ 状态维护（在建/过期/归档）。

## 4. 数据对象：ProjectManagerProfile

| 字段 | key | 必填 | 说明 |
|---|---|---|---|
| 经理ID | `manager_id` | 是 | 主键，如 PM-0001 |
| 姓名/脱敏展示名 | `display_name` | 是 | 列表默认脱敏（如 张**），明细按权限 |
| 所属组织 | `organization` | 是 | 公司/部门/项目部 |
| 专业 | `specialty` | 是 | 建筑工程/市政/公路等 |
| 注册证书 | `reg_cert_type` | 是 | 一级建造师/二级建造师等 |
| 注册编号 | `reg_cert_no` | 是 | 唯一，校验格式 |
| 证书等级 | `cert_level` | 是 | 一级/二级 |
| 有效期 | `cert_valid_until` | 是 | 过期自动 expired |
| 继续教育/安全证书状态 | `edu_safety_status` | 是 | valid / expiring / expired / pending |
| 可担任项目类型 | `eligible_project_types[]` | 是 | 与项目类型匹配 |
| 地区限制 | `region_restriction` | 否 | 如仅限河北省 |
| 历史业绩 | `performance_refs[]` | 否 | 回链 F006 PerformanceRecord |
| 当前在建项目 | `active_projects[]` | 否 | 项目ID + 预计结束 |
| 预计可用日期 | `expected_available_at` | 否 | |

| 最后核验时间 | `verified_at` | 否 | |
| 资料责任人 | `data_owner` | 是 | |
| 状态 | `status` | 是 | active / unavailable / expired / pending_verification / archived |

## 5. 输入/输出与证据要求

- 输入：人事/数据管理员导入（现有"注册建造师清单（未完善）"为候选来源，脱敏）。
- 输出：ProjectManagerProfile + 状态流转。
- 证据要求：注册证书、有效期、社保/在岗、业绩、在建状态均须证据文件支撑；无证据 = pending_verification。

## 6. 业务规则

### 6.1 硬条件验证（匹配时，先验证后计分）

对每位候选经理按序验证，任一不满足或**无法核验** → 该经理**不能计入"满分可投标"**：

1. 专业匹配（specialty ⊆ 招标要求）；
2. 注册证书类型与等级匹配（reg_cert_type + cert_level）；
3. 有效期（cert_valid_until 未过，且继续教育/安全证书有效）；
4. 社保/在岗（在岗证据有效，非挂靠）；
5. 业绩满足招标要求（年限/规模/类型，回链 performance_refs）；
6. 在建冲突（active_projects 与招标项目时间不冲突）；
7. 可用状态（availability=available；占用中但预计可用日期早于招标要求时间可视为可用，须注明）；
8. 信用/处罚状态无不利项（如有记录须人工复核）。

### 6.2 候选与推荐

- 可选择多个候选经理；必须明确主推荐（primary）/ 备选（backup）与各自证据。
- 主推荐/备选标记由投标专员在匹配界面设置，留存审计。

### 6.3 真实性红线

- 不得生成不存在的项目经理或证书资料；数据只能来自导入/录入 + 人工核验。
- 无法核验的字段 → pending_verification / "待核实"，禁止推断满足。

### 6.4 导入映射规则（2026-08-27 实测，详见 §14）

1. 源清单占位符（"后续补充"/"不用填"/空）→ 映射为"待补"，不导入占位值；
2. 专业 11 类列勾选 → 合并为多专业（specialty / eligible_project_types），空列不产生值；
3. 等级列解析为 reg_cert_type + cert_level（"一级建造师"→ 一级/建造师）；
4. 业绩按"负责项目经理"姓名 join 为 performance_refs（同名多业绩合并，重名待人工核实）；
5. 在施状态 → availability（是→occupied，否→available，空→待核实）；
6. 源清单标注"未完善" → 导入后默认 `pending_verification`，经核验人（测试期暂定项目负责人）核验转 active；
7. 缺列字段（证书有效期/安全证书/证据文件等）→ "待补"，不推断、不生成。

## 7. 失败/空态/异常状态

| 状态 | 处置 |
|---|---|
| 无可用经理 | 匹配结果 blocked_missing_data / 明确提示"无合格可用项目经理" |
| 证书过期/临期 | expired / 提前告警数据责任人 |
| 证据缺失 | pending_verification，不参与满分 |
| 在建冲突 | 该经理不计入满分，可提示预计可用日期 |
| 权限不足 | 明细隐藏，仅审批层可见 |

## 8. API 目标态契约

```text
POST   /api/v1/managers               # 新增/导入经理
GET    /api/v1/managers               # 名录列表（脱敏）
GET    /api/v1/managers/{id}          # 明细（权限控制）
PATCH  /api/v1/managers/{id}          # 更新状态/在建/可用日期（审计）
POST   /api/v1/managers/{id}/verify   # 核验（数据责任人）
GET    /api/v1/managers/{id}/match    # 与指定招标要求硬条件预检
```

## 9. 权限、数据隔离、审计和合规

- 个人信息最小化：脱敏展示名；明细 restricted；审计导入/修改/核验。
- 信用/处罚仅限企业合法维护范围（有证据），无证据不录入。
- 资料责任人制：`data_owner` + `verified_at`。

## 10. 验收标准与测试计划

- 验收：①字段/状态机冻结；②硬条件验证规则实现且可解释；③主推荐/备选机制；④无虚构数据（生成校验用例）；⑤现有清单可脱敏导入并标 pending_verification。
- **测试期范围**（2026-08-27）：核验人暂定项目负责人；最小闭环验证 = 建造师清单导入 → 名录结构化 → 硬条件筛选 → 候选输出，用真实清单跑通。
- 测试计划：硬条件逐项用例（专业/证书/有效期/社保/业绩/在建/可用/信用）；过期与临期用例；权限用例。

## 14. 实测导入源盘点（2026-08-27，`3.注册建造师清单（含在施状态).xlsx`）

| 源列 | ProjectManagerProfile 映射 | 实测 | 处置 |
|---|---|---|---|
| 姓名 | `display_name` | 1181 行，去重 1145 人 | 导入后脱敏展示 |
| 建筑/市政/机电/公路/铁路/民航/水利水电/港口航道/矿业/通信 专业列 | `specialty` + `eligible_project_types[]` | 11 类专业列勾选 | 勾选合并为多专业 |
| 等级 | `reg_cert_type` / `cert_level` | 有值（一级/二级建造师） | 解析等级 |
| 注册编号 | `reg_cert_no` | **1181 条全为"后续补充"** | 映射为"待补" |
| 联系电话 | `phone`（F006 4.3） | **1181 条全为"后续补充"** | 映射为"待补" |
| 在施状态 | `availability` | 有值（是/否） | 是→occupied / 否→available |
| 在施项目名称 | `active_projects[]` | 有值 | 登记项目名（ID 待补） |
| （无此列） | `organization` | 缺失 | 待补 |
| （无此列） | `cert_valid_until` | **缺失** | 待补 → 影响有效期硬条件 |
| （无此列） | `edu_safety_status`（B 证/继续教育） | **缺失** | 待补（双项目演练已暴露） |
| （无此列） | `evidence_refs[]`（证书扫描件） | **缺失** | 待补（R017 OCR 通道可补） |
| 业绩清单"负责项目经理"列 | `performance_refs[]` | 844 条业绩含项目经理名 | 按姓名 join，同名多业绩合并 |

**导入结论**：专业/等级/在施状态可结构化导入；注册编号、有效期、安全证书、证据为硬缺口 → 全部记录默认 `pending_verification`，硬条件验证遇缺失即阻断（不推断满足）；待补字段经核验人补充证据后转 active。
