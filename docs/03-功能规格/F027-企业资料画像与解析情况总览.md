# F027：企业资料画像与解析情况总览

- **状态**：定稿
- **版本**：v1.0（2026-09-22）
- **关联**：F006（企业资料库）、F007（项目经理）、F008（评分规则与满分准入）、F010（原型）、F022（核验运行时）、ADR-001（四层边界）

## 1. 背景与目标

企业资料已于 2026-09-14 全量入库（F006 §15：资质 28 / 业绩 844 / 项目经理 1181 / 人员 6398 / 证据 13）。此后缺少一个回答「**每个常用投标评分维度上，我们的资料解析、核验与证据情况到底怎么样、缺什么**」的只读视图。

本规格新增「企业画像」总览：按招标文件常见评分维度展示企业资料覆盖情况，并按四分类拆分口径，用于指导补录与核验优先级。

**边界（红线）**：本视图只做**事实聚合**（计数、字段覆盖率、日期覆盖、证据回链率），**不输出资格结论、评分预测、补齐后能否满分或任何投标建议**；逐项匹配结论仍以匹配引擎输出为准（F008 / F023），最终投标决定始终由人作出（ADR-001）。

## 2. 四分类口径（2026-09-22 业主建议采纳）

招标要求按判定性质拆为四类；本视图的每个维度标注其所属分类（可多属）。口径对齐 F008 §2 四类结论的输入侧：

| 分类 | key | 判定性质 | 系统处置 | 对应 F008 概念 |
|---|---|---|---|---|
| 硬性资格/响应要求 | `hard` | 满足或不满足（二值） | 缺证据即阻断（`blocked_missing_data`），不得推断满足 | `hard_requirement` / `qualification_result` |
| 客观可计算评分项 | `objective` | 可按公式复算（报价、业绩数量、人员证书、工期等） | 公式与输入齐全才自动计算；不可计算时 `not_calculable`，不填 0 冒充 | `scored_requirement`（`score_nature=objective`） |
| 主观评审项 | `subjective` | 人工评审（技术方案、服务方案、组织措施等） | 系统不打分；进入内部质量评审，未完成评审则 `manual_review` | `scored_requirement`（`score_nature=subjective`） |
| 企业内部准入项 | `internal` | 企业侧内部条件（资料完整性、资源可用性、在施状态等） | 不属评标项，但作为内部满分准入（F008 §6.1）的输入 | `operational_readiness` / `internal_admission` |

## 3. 维度与数据来源映射

前 10 项为招标文件常见评分维度（2026-09-22 业主给定清单），后 5 项为企业内部准入项。每维度给出企业侧数据来源与常见缺口；**来源为空即如实展示「无资料/不属资料库」**，不编造。

| # | 维度 | key | 分类 | 企业侧来源 |
|---|---|---|---|---|
| 1 | 投标报价 | `bid_price` | objective | 无（报价必须授权人工录入 `score_inputs.quoted_price`，F008 §4.2；系统不生成/推荐/假定报价） |
| 2 | 施工组织设计或技术方案 | `technical_plan` | subjective | 无（标书编制产物，企业资料库不承载；匹配输出「待内部质量评审」） |
| 3 | 工期与进度保障 | `schedule` | objective + subjective | 业绩开竣工日期覆盖（`performances.awarded_at/completed_at`） |
| 4 | 质量保证措施 | `quality` | subjective | 资质库质量/ISO 体系类记录（当前无） |
| 5 | 安全生产与文明施工 | `safety` | hard + subjective | 安许证（qualifications）、项目经理安全 B 证（managers） |
| 6 | 项目经理及技术团队 | `managers_team` | hard + objective | 项目经理名录（managers）、人员库建造师/职称（personnel） |
| 7 | 类似工程业绩 | `similar_performance` | hard + objective | 业绩台账（performances：类型/金额/竣工日期/证据回链） |
| 8 | 机械设备和资源配置 | `equipment` | objective + subjective | 无（F006 未建设备台账；F008 已定义 `equipment_list` 证据种类） |
| 9 | 绿色施工、环保和 BIM | `green_bim` | objective + subjective | 无（资质库无此类认证/证书） |
| 10 | 企业信用、奖项及履约记录 | `credit_awards` | hard + objective | 信用评级（qualifications）、已完工业绩履约事实（performances）；奖项无台账 |
| 11 | 证据回链完整性 | `evidence_integrity` | internal | 各类记录 `evidence_refs` 覆盖率 |
| 12 | 核验状态 | `verification_status` | internal | 各类记录 `pending_verification` 计数（未核验不参与匹配，F022 §2.6） |
| 13 | 有效期管理 | `validity_management` | internal | expired 计数、90 天内临期计数（资质/经理证书/人员证书） |

| 15 | 关键字段完整性 | `field_completeness` | internal | 证书编号/等级/有效期等待补字段计数（`__待补__` 哨兵或 NULL） |

## 4. 聚合口径

- `coverage`（资料覆盖状态，四值，事实性）：
  - `active`：该维度引用的资料中存在已核验生效（active）记录；
  - `pending`：有记录但全部未核验（pending_verification 等）；
  - `missing`：无任何记录（如实展示缺口）；
  - `not_applicable`：不属企业资料库承载（报价、技术方案等投标编制产物）。
- `facts[]`：仅允许数据库计数、字段覆盖率、日期覆盖与台账日期统计（如「近五年竣工 N 条」须标注按台账竣工日期、截至当日）。金额汇总只对有值记录累加并标注台账口径。
- `gaps[]`：事实性缺口陈述（如「844 条业绩中 841 条无证明文件回链」），不出现「需保证满分」「大概率满足」等判断词。
- 待补口径：导入哨兵 `__待补__` 与 NULL 均计为待补。
- 证据回链两级口径（实测发现必须区分，2026-09-22）：`evidence_refs` 非空计为**有回链**；其中排除 `ledger:`（汇总台账行回链，指回导入批次台账文件）与 `cert_no:`（编号留痕）后的引用计为**挂单项证明文件**（扫描件/合同/验收单等具体材料）。大量记录仅有台账行回链（如业绩 846/849、项目经理 1181/1182）——台账行回链可用于溯源，但不等于该条记录的单项证明文件；画像必须分开计数，不得以"有回链"冒充"单项证据充分"。
- 聚合只读：不写库、不写审计（与其他 GET 一致）、不触发任何任务。

## 5. API 契约

```text
GET /api/v1/enterprise/overview
```

- 权限：`enterprise:read`（投标专员/经营负责人；匿名 403）。
- 响应（摘要）：

```json
{
  "request_id": "…",
  "note": "事实聚合声明（不构成资格结论/评分/投标建议）",
  "summary": {
    "as_of": "2026-09-22",
    "kinds": [ { "kind": "qualifications", "label": "资质", "total": 28, "by_status": {…}, "with_evidence": 6 } , … ],
    "records_total": 8452, "active_total": 0, "pending_total": 8452, "expired_total": 0, "rejected_total": 0
  },
  "category_definitions": [ { "key": "hard", "label": "硬性资格/响应要求", "note": "…" } , … ],
  "dimensions": [ { "key": "safety", "label": "安全生产与文明施工", "categories": ["hard", "subjective"],
                    "coverage": "pending", "sources": [ { "kind": "qualifications", "label": "安全生产许可证", "total": 1, "by_status": {…}, "with_evidence": 1 } ],
                    "facts": ["…"], "gaps": ["…"], "remark": "判定口径说明" } ]
}
```

- 空库不报错：全部计数为 0、coverage 为 `missing`/`not_applicable`，不得输出编造数字。

## 6. 页面（prototype/profile.html「企业画像」）

- 顶部统计卡：五类记录总数、已核验/待核验/已过期、证据回链总数。
- 按四分类分节展示维度卡：每卡含分类徽标、coverage 徽标、来源表（记录数/状态分布/证据回链）、事实清单、缺口清单、判定口径备注。
- 事实用中性色、缺口用警示色；页面底部固定声明：本页为资料解析情况画像，匹配结论以逐项匹配结果为准，满分仍须经营负责人人工审批。
- 导航挂「企业资料库（后台）」之后；步骤条不占用主旅程位（后台视图）。

## 7. 验收标准

1. 四分类与 15 个维度按 §3 输出，分类标签与 F008 概念对应正确。
2. 空库时接口正常返回全 0/missing，不出现编造数字；sqlite 与 PostgreSQL 双跑一致。
3. 计数与库内事实一致（抽样核对资质/业绩/项目经理/人员四类）。
4. 页面与响应不出现资格结论或投标建议措辞；待核验记录不被描述为「已具备」。
5. 匿名 403；两级角色可读。
