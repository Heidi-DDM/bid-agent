# F006-企业资质业绩资料库

- **需求来源**：R006 ｜ **状态**：draft（Iteration 2 冻结）
- **关联**：F003（Material 契约）、F005（advantage 子卡）、F008（匹配）、`企业资料台账20260821/`（未入库，仅盘点）

## 1. 背景与目标

- **背景**：公司已有部分资料清单（注册建造师清单、技术职称人员清单、已完工项目清单，均标注"未完善"；典型招投标文件）。当前无结构化资料库，`advantage` 子卡为占位。
- **目标**：建立最小企业资质/业绩资料库（Material 治理），支撑 F008 逐项匹配；每个条目有有效期、证据文件、数据责任人；缺失标"待补/待核实"。

## 2. 非目标

- 不建设完整人力资源系统；不引入未授权私有数据；不推断缺失资料。

## 3. 用户角色与端到端步骤

| 角色 | 步骤 |
|---|---|
| 数据管理员 | 导入/维护资质、业绩、证据文件 → 核验 → 标记责任人 |
| 投标专员 | 查看资料、选择匹配用资料 |
| 法务/人事 | 确认资料使用合规与个人信息边界 |

端到端步骤：清单盘点 → 导入（脱敏）→ 结构化（Material）→ 核验/补证据 → 用于匹配（F008）。

## 4. 数据对象

### 4.1 企业资质（QualificationRecord）

| 字段 | key | 必填 | 说明 |
|---|---|---|---|
| 资质ID | `qualification_id` | 是 | 主键 |
| 资质类别 | `category` | 是 | 如建筑工程施工总承包、设计甲级、ISO 认证等 |
| 等级 | `level` | 否 | 特级/一级/甲级等 |
| 专业 | `specialty` | 否 | |
| 有效期 | `valid_from` / `valid_until` | 是 | 过期状态自动判定 |
| 发证机关 | `issuer` | 否 | |
| 证据文件引用 | `evidence_refs` | 是 | 回链 F003 evidence_file |
| 数据责任人 | `data_owner` | 是 | |
| 最后核验时间 | `verified_at` | 否 | |
| 状态 | `status` | 是 | active / expired / pending_verification / archived |

| 字段 | key | 必填 | 说明 |
|---|---|---|---|
| 业绩ID | `performance_id` | 是 | 主键 |
| 项目名称 | `project_name` | 是 | |

### 4.3 证据文件（evidence_file，F003 Material 之一）

- 文件ID、类型（证书扫描件/合同/中标通知书/验收单）、存储引用、哈希、上传人、上传时间、有效期、密级（internal/confidential）。

## 5. 输入/输出与证据要求

- 输入：现有清单（xlsx，脱敏）、人工录入。
- 输出：结构化资料库记录。
- 证据要求：资质/业绩必须挂证据文件；无证据 = pending_verification，不参与"满分"判定。

## 6. 业务规则

1. 缺失字段显示"待补/待核实"，禁止编造（如证书等级未填不得推断）。
2. 有效期校验：过期 → expired，不得用于满分判定。
3. 数据责任人制：每个条目有人负责核验，核验留痕（verified_at + 审计）。
4. 未授权数据不接入（ADR-001 非目标）。
5. 导入的现有清单若标注"未完善"，其记录默认为 pending_verification，须人工核验。

## 7. 失败/空态/异常状态

- 空态：资料库为空 → 匹配层输出"不可判定/待补材料"。
- 证据缺失：pending_verification。
- 过期：expired 并告警数据责任人。
- 权限不足：企业私有数据仅 enterprise_read 以上可见。

## 8. API 目标态契约

```text
POST   /api/v1/qualifications        # 导入/新增资质
POST   /api/v1/performances          # 导入/新增业绩
POST   /api/v1/evidences             # 上传证据文件
GET    /api/v1/qualifications/{id}
GET    /api/v1/performances/{id}
POST   /api/v1/materials/{id}/verify # 核验（F003）
```

## 9. 权限、数据隔离、审计和合规

- 私有资料 permission_scope = enterprise_read 起步；明细限 restricted。
- 导入/修改/核验全审计；企业资料不入 Git（`.gitignore`）。

## 10. 验收标准与测试计划

- 验收：①最小字段集冻结；②可导入现有清单（脱敏样例）；③有效期/证据/责任人校验生效；④缺失标"待补"。
- 测试计划：导入用例、过期用例、证据缺失用例、权限用例。
