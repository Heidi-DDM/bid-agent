# F006-企业资质业绩资料库

- **需求来源**：R006 ｜ **状态**：定稿 v1.1（Iteration 2 冻结）
- **关联**：F003（Material 契约）、F005（解析链路）、F007（项目经理引用）、F008（匹配）、`企业资料台账20260821/`（未入库，仅盘点）

## 1. 背景与目标

- **背景**：公司已有部分资料清单（注册建造师清单、技术职称人员清单、已完工项目清单，均标注"未完善"；典型招投标文件）。当前无结构化资料库，`advantage` 子卡为占位。
- **目标**：建立最小企业资质/业绩/人员资料库（Material 治理），支撑 F008 逐项匹配；每个条目有有效期、证据文件、数据责任人；缺失标"待补/待核实"。人员（注册建造师/技术职称）归本库统一承载，R007 在其上做项目经理视角筛选。
- **2026-08-26 实测盘点**（企业素材全量，详见 §15）：3 份 xlsx（建造师/职称/业绩）可结构化导入；资质/安许证/岗位证书为**空壳 xls + 扫描件 PDF**（无文本层）→ 走 R017 OCR 通道或人工录入；业绩证据 5 份 PDF 有文本层可登记。

## 2. 非目标

- 不建设完整人力资源系统；不引入未授权私有数据；不推断缺失资料。
- 不解析加密固化格式（.gef/.etb）；不绕过任何技术保护。

## 3. 用户角色与端到端步骤

| 角色 | 步骤 |
|---|---|
| 数据管理员 | 导入/维护资质、业绩、人员、证据文件 → 核验 → 标记责任人 |
| 投标专员 | 查看资料、选择匹配用资料 |
| 法务/人事 | 确认资料使用合规与个人信息边界 |

端到端步骤：清单盘点 → 导入（脱敏）→ 结构化（Material）→ 核验/补证据 → 用于匹配（F008）。

### 4.4 证据文件（evidence_file，F003 Material 之一）

- 文件ID、类型（证书扫描件/合同/中标通知书/验收单）、存储引用、哈希、上传人、上传时间、有效期、密级（internal/confidential）。
- **OCR 产物扩展**：`ocr_confidence`（字段级置信度）、`page_no`（页码定位）、`source_hash`（原文 hash，不可变）。低置信度字段 → 人工复核，不静默入库。

## 5. 输入/输出与证据要求

- 输入：现有清单（xlsx，脱敏）、人工录入、OCR 结构化产物（R017）。
- 输出：结构化资料库记录。
- 证据要求：资质/业绩/人员必须挂证据文件；无证据 = pending_verification，不参与"满分"判定。

## 6. 业务规则

1. 缺失字段显示"待补/待核实"，禁止编造（如证书等级未填不得推断）。
2. 有效期校验：过期 → expired，不得用于满分判定。
3. 数据责任人制：每个条目有人负责核验，核验留痕（verified_at + 审计）。
4. 未授权数据不接入（ADR-001 非目标）。
5. 导入的现有清单若标注"未完善"，其记录默认为 pending_verification，须人工核验。
6. **OCR 产物规则**（R017）：OCR 文本必须携带原文 hash + 字段级置信度 + 页码；置信度 < 阈值（默认 0.9，可配置）→ 人工复核；OCR 结果不覆盖原文 raw。
7. **导入映射规则**（2026-08-26 实测，详见 §15）：
   - 空壳 xls（资质/安许证/岗位证书清单）= 无业务数据 → 不导入，走人工录入 + R017 OCR；
   - 扫描件 PDF（资质/安许证）→ R017 OCR → 人工复核后入库；
   - 有文本层证据 PDF（7 目录合同/验收）→ 直接提取登记为业绩证据；
   - 字段值为"后续补充"等占位符 → 映射为"待补"，不导入占位值。

## 7. 失败/空态/异常状态

- 空态：资料库为空 → 匹配层输出"不可判定/待补材料"。
- 证据缺失：pending_verification。
- 过期：expired 并告警数据责任人。
- 权限不足：企业私有数据仅 enterprise_read 以上可见。
- OCR 低置信度：字段级标记，进入人工复核队列，不静默入库。

## 8. API 目标态契约

```text
POST   /api/v1/qualifications        # 导入/新增资质
POST   /api/v1/performances          # 导入/新增业绩
POST   /api/v1/personnel             # 导入/新增人员（建造师/职称/岗位）
POST   /api/v1/evidences             # 上传证据文件
GET    /api/v1/qualifications/{id}
GET    /api/v1/performances/{id}
GET    /api/v1/personnel/{id}
POST   /api/v1/materials/{id}/verify # 核验（F003）
POST   /api/v1/ocr/route             # Document Router：提交文件 → 路由/OCR → 结构化 JSON（R017）
```

## 9. 权限、数据隔离、审计和合规

- 私有资料 permission_scope = enterprise_read 起步；明细限 restricted。
- 导入/修改/核验全审计；企业资料不入 Git（`.gitignore`）。
- OCR 本地处理优先（数据不出内网）；云 OCR/多模态 LLM 需法务确认（R017）。

## 10. 验收标准与测试计划

- 验收：①最小字段集冻结（含人员扩展）；②可导入现有清单（注册建造师/技术职称/已完工项目，映射规则生效）；③有效期/证据/责任人校验生效；④缺失标"待补"；⑤OCR 产物带置信度/页码、低置信度入人工复核；⑥空壳 xls 不误导入。
- 测试计划：导入用例、过期用例、证据缺失用例、权限用例、OCR 路由/置信度/空壳用例。
