# F018-运行时技术基线与本地部署

- **需求来源**：R018 ｜ **状态**：定稿草案 v1.0（2026-08-31）
- **关联**：F003、F004-F011、F017、F025、ADR-001、ADR-002

## 1. 目标与边界

把当前脚本和静态原型运行在一个可重复启动、可审计、数据不出内网的本地环境中，为农大单项目薄切片提供工程基线。

非目标：不做生产集群、高可用、定时采集、批量任务、自动投标；不把企业资料提交 Git。

## 2. 推荐组件

| 组件 | 选型/约束 |
|---|---|
| HTTP 服务 | FastAPI + Uvicorn，Python 3.11+ |
| 数据访问 | SQLAlchemy + Alembic；数据库使用 PostgreSQL + pgvector |
| 文件存储 | 本地受控目录或内网 MinIO；文件不直接存数据库 |
| 解析/OCR | pdftotext、python-docx/textutil、tesseract chi_sim；复用 F017 规则 |
| 任务执行 | 数据库任务表 + 单 worker；不得用不可追踪的临时线程推进状态 |
| 模型 | DeepSeek API 仅限 public 数据；企业 OCR/embedding 使用公司批准的本地/内网模型；接口采用结构化 JSON |
| 检索 | F025 混合检索：PostgreSQL 全文/关键词 + pgvector + metadata filter + 可选本地 reranker |
| 测试 | pytest、py_compile、黄金样本回归；命令固定写入 README |

## 3. 环境配置

配置通过 `.env` 或部署平台注入，至少包括 `DATABASE_URL`、`OBJECT_STORE_ROOT`、`MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_REQUEST_TIMEOUT_SECONDS`、`OCR_LANG`、`APP_ENV`、`LOG_LEVEL`、`PGVECTOR_ENABLED`、`EMBEDDING_MODEL`、`EMBEDDING_DIM`、`RERANKER_ENABLED`、`RAG_TOP_K`、`RAG_CHUNK_SIZE`、`RAG_CHUNK_OVERLAP`、`DEEPSEEK_PUBLIC_ONLY=true`。提交前执行敏感文件扫描；`.env`、真实路径、模型密钥不得进入 Git。

MacBook Air M5 16GB 的测试期默认值：本地 OCR + 量化 embedding（BGE-M3 或同级）+ 单 worker + 批量 4-8；不默认部署大于 7B 的本地生成模型，也不承诺并发推理能力。实际模型、量化方式、维度和批大小必须记录到部署清单。

## 4. 服务进程与生命周期

1. API 启动并执行数据库迁移检查。
2. worker 轮询 `analysis_jobs`，按状态机领取任务并写入心跳。
3. 文件处理先写临时文件，完成哈希和病毒/格式检查后再转入不可变对象路径。
4. 进程异常时任务保持 `running` 超时可恢复为 `retryable`，不得直接把项目推进到下一业务状态。
5. 所有异常带 `request_id`/`job_id`，日志只记录元数据和错误摘要。

## 5. 健康检查与可观测性

- `GET /healthz`：进程存活，不访问业务数据。
- `GET /readyz`：数据库、文件根目录、OCR 命令和模型适配器（若启用）可用性检查。
- 记录 job 开始/结束、耗时、输入哈希、输出版本、错误码；禁止记录完整招标原文、身份证号、手机号。
- 运行数据和日志写入受控目录，不写入仓库目录。

## 6. 安全与合规

- 开发环境默认绑定 `127.0.0.1`；内网部署再配置反向代理和 TLS。
- 私有资料处理链路禁止外发；模型适配器必须有“本地/内网”配置检查。
- RAG 服务在 embedding、检索和 rerank 前均执行权限过滤；`DEEPSEEK_PUBLIC_ONLY` 关闭时 `/readyz` 失败，禁止启动涉及外部模型的任务。
- 生产式数据库使用独立账号、最小权限和加密备份；个人信息默认脱敏展示。

## 7. 操作步骤

1. 创建虚拟环境并安装锁定依赖。
2. 复制配置模板，填写本机数据库和文件存储路径。
3. 启动 PostgreSQL，执行 `alembic upgrade head`。
4. 启动 API 和单 worker，检查 `/healthz`、`/readyz`。
5. 执行黄金样本回归，再开放农大文件上传。
6. 验收结束后清理临时文件，保留数据库快照和审计记录。

## 8. 验收与测试

- 新机器按文档可完成启动；依赖版本可复现。
- API/worker 任一进程重启不丢任务、不产生重复 Material。
- 缺少数据库、OCR 或模型时 `/readyz` 明确失败，业务任务进入可解释错误状态。
- `pytest`、`py_compile`、农大黄金样本命令均可执行；CI 与本地命令一致。
- pgvector、embedding 服务和权限负例纳入 `/readyz` 与验收；任一未就绪时不创建成功的索引/检索任务。
