# F022-企业资料导入、OCR 与核验运行时

- **需求来源**：R022 ｜ **状态**：定稿草案 v1.1（2026-08-31）
- **关联**：F006、F007、F017、F019、F020、ADR-001

## 1. 目标

将农大匹配所需的最小企业资料导入企业私有库：资质、项目经理、技术团队、安全员、业绩、社保、信用、保证金和投标文件证据。所有记录默认待核验，核验后才能参与匹配。企业资料是跨项目的后台基础数据，不在单个招标项目中再次选择。

## 2. 导入顺序与操作

1. 数据管理员创建企业资料导入批次，登记来源、责任人和授权范围。
2. 导入建造师、职称、岗位证书、业绩 XLSX；列名按 F006 映射。
3. 空值、`后续补充`、`不用填`、占位符统一为 `__待补__`；Excel 序列日期按 1899-12-30 转 ISO，越界日期标待核实。
4. 上传资质/安许证/合同/验收证据文件，计算哈希并关联记录。
5. Document Router 分流文本文件和扫描件；扫描件调用 tesseract `chi_sim`，输出页码和字段置信度。
6. 低于页面 0.60 或字段 0.90 的结果进入复核队列；人工确认需填写修正值、依据和时间。
7. 数据管理员核验记录，状态由 `pending_verification` 转 `active`；过期自动转 `expired`。

## 3. 农大最小资料集

至少准备并核验：建筑工程施工总承包资质、安许证、1 名建筑专业项目经理（注册证/B 证/无在建/社保）、2 名 C 证安全员、4 个技术专业覆盖、信用三查、财务审计或银行资信、投标保函、投标函/报价、投标人及项目经理类似业绩。

当前缺失的财务审计材料必须保持 `pending_verification`，不能用“实际中标”事实回填。

## 4. 数据质量与个人信息

- 每条记录必须有 `material_id`、`evidence_refs`、`data_owner`；无证据不可转 active。
- 项目经理姓名和电话在列表中脱敏，完整明细仅授权角色可读。
- 岗位证书长期有效的公司口径须保留确认记录，不擅自生成到期日。
- 导入批次可回滚到导入前版本，但不得删除审计事件。

## 5. 验收与测试

- 三份 XLSX 可重复导入且无重复主键；占位符和日期转换结果可抽样核对。
- OCR 结果包含 `source_hash`、页码、页面/字段置信度和复核状态。
- 过期、缺证据、低置信度、权限不足均不能进入匹配有效证据集合。
- 项目经理筛选结果仅来自已存在且已核验人员，候选为空时输出阻断。
- 匹配服务每次自动读取截至 `as_of` 的 `active` 资料快照；投标专员不可通过前端勾选、替换或绕过资料核验改变匹配输入。补录材料必须生成新 Material 版本，核验通过后由重算流程读取。
- 企业资料对象存储和数据库均不写入 Git、不发送到外部模型。
