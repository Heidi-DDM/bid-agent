# F023-匹配、评分与准入运行时服务

- **需求来源**：R023 ｜ **状态**：定稿草案 v1.4（2026-09-15）
- **关联**：F008、F009、F019、F020、F021、F022、F025、ADR-001、ADR-002、`scripts/matching/engine.py`

## 1. 目标

将现有确定性引擎服务化并保存可重放快照。规则、证据和时点是输入；服务只产生证据化核查结果，不作企业投标决策。

## 2. 执行步骤

1. 解析任务成功后，编排器按项目当前确认的招标文件/澄清版本、RuleSet 版本和 `as_of` 自动创建首次匹配任务；投标专员不在项目内选择企业资料或直接触发首次匹配。
2. F025 RAG 先按权限、项目/标段、版本和 `as_of` 召回 L2 条款及 L3 候选证据；召回结果只作为候选输入，必须保留引用。
3. 服务锁定规则快照和截至 `as_of` 的企业 `active` 结构化证据快照，校验标段/联合体范围；不能因向量相似度或模型置信度直接满足规则。
4. 先以 `diagnostic` 模式全量执行，得到 hard/scored/action 三类矩阵。
4. 再以 `gate` 模式计算业务状态；短路项以外的未执行项必须明确展示。
   **实现口径（v1.4，2026-09-15）**：`runtime/core/matching.run_match(mode="gate")` 内部两次调用引擎并合并：
   `matrix / blocked / pending / review` 取诊断全量（每条要求都有结论与原因，处置队列列出全部缺项而非短路前第一项）；
   门禁短路后未执行到的条目逐条 `gate_executed=false`，并在 `coverage.short_circuited[]` 点名；`coverage` 字段：
   `declared / executed / complete`（本次实际执行＝全量）+ `gate_executed / gate_complete / short_circuited`。
   业务结论以全量矩阵如实汇总（硬性失败在两种模式下均在 blocked 内，一票否决结论不变；门禁在截断矩阵上算出的
   scoring/readiness 是空集上的"满分/就绪"，不采用）。`MatchRun.mode` 仍为 `gate`（驱动准入）。
   **未执行项标识**：结果页对"有运行但无 MatchItem"的要求返回 `match=not_evaluated`（旧版短路运行遗留），不得默认
   `unverifiable` 冒充"已判定缺证"（F008 覆盖门禁）。
5. 生成四类结论：资格/响应性、当前评分、投标准备度、内部准入。
6. 将结果、输入快照、引擎版本、规则版本和耗时写入 `match_runs`/`admission_results`。

## 3. 农大规则与判定

使用 20 条农大规则：hard 12、scored 4、action 4。NQ-H-007 财务材料缺失时必须为 `unverifiable` 并映射 `blocked_missing_data`；主观评分项未完成内部评审不得计入内部满分；报价必须由人员录入，系统不生成报价。

## 4. 重算和失效

- 招标文件澄清、补遗、企业证据变更、人工修正或规则版本变更会使旧结果 `stale`。
- `stale` 结果不可创建审批；必须引用新版本重新执行。
- `as_of` 以前未核验的证据、过期证据、缺失哈希证据均为 `unverifiable`。
- RAG 召回不到候选证据、权限过滤后无可用证据或引用不完整时为 `unverifiable`/`blocked_missing_data`；只有结构化证据核验通过后才允许规则执行为 `satisfied`。
- 同一项目可保留多个运行结果，但只有最新有效结果可驱动状态迁移。
- 人工补录或解析复核通过后，前端调用重算接口；重算必须引用新 Material/证据版本。结果查看接口为只读，不得隐式创建运行任务。

## 5. 状态迁移门禁

`parsed → matching` 仅在解析任务成功或人工确认后由编排器自动迁移；匹配结果有缺失进入 `blocked_missing_data`，明确硬性不满足进入 `blocked_hard_requirement/not_qualified`；全部满足才进入 `qualified_full_score`，然后才能进入 `pending_bid_approval`。

## 6. 验收与测试

- 农大运行输出 `declared=20`、`executed=20`、`complete=true`，矩阵逐条可回链。
- 缺财务、过期资质、无 B 证、在建冲突、保证金金额错误、报价超限价等负例均按 F008 状态映射。
- 规则/证据/澄清版本变更后旧结果不可继续审批，新结果可重放。
- 只有 `internal_admission_eligible=true` 才允许调用审批创建接口。
- 首次匹配不得早于完整招标文件解析完成；重复的解析完成事件、页面刷新和结果查询不得新增匹配 run；补录核验后允许且只允许创建引用新证据快照的重算 run。
- 匹配 run 必须保存 RAG `retrieval_run_id`、查询过滤条件、候选 chunk ID 和结构化核验结果；相同材料/规则/证据/索引版本可重放，向量分数不得进入准入公式。
