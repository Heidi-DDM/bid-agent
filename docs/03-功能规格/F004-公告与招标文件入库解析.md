# F004-公告与招标文件入库解析

- **需求来源**：R004、R005、R014、R015 ｜ **状态**：定稿 v1.3（R004 入库部分冻结；解析部分按 R005/F021 联通；采集策略/分页口径于 2026-09-08 收口）
- **关联**：ADR-001、F002、F003、F005、`docs/合规数据源清单.md`、`raw/`、`scripts/`

## 1. 背景与目标

- **背景**：既有采集与发布层已实现公告采集/事实卡/日报（`scripts/`、`schema/` v0.3.x，manual_trigger）；新增需求要求能获取**招标文件**（不止公告）并入库解析，且测试期保持手动触发。
- **目标**：合规数据源 + 手动触发（人工粘贴公告 / 上传招标文件 / 单条 URL）→ 不可变原文入库（Material 治理，对齐 F003 契约）→ 解析（主卡、资格要求、评分规则、时间线、废标条款）→ 字段级引用；测试期不启动 scheduled。
- **定稿范围声明（2026-08-26，R004）**：本次冻结**入库链路**（合规数据源清单、manual_trigger 通道、不可变原文 + hash + 版本、去重、红线、intake API）；**解析契约**（主卡/子卡/字段级引用）归 R005，随 F005 定稿，本规格不提前冻结。

## 2. 非目标

- 7×24 全网监控、全平台自动抓取、自动定时采集（R015 后置）；
- 登录/付费/非公开内容抓取；绕过技术保护；任何非合规采集；
- 招标文件解析契约细节（R005 / F005 冻结）。

## 3. 用户角色与端到端步骤

| 角色 | 步骤 |
|---|---|
| 投标专员 | 粘贴合规公告 URL/正文、上传招标文件（docx/pdf）→ 查看解析结果 → 人工复核 |
| 数据管理员 | 维护数据源合规记录（`docs/合规数据源清单.md` + `templates/数据源合规记录模板.md`） |
| 法务 | 审核数据源清单（签字门槛） |

端到端步骤：手动触发 → 原文保存（不可变 raw + hash）→ 解析 → 主卡/子卡生成 → 字段级引用 → 人工复核/门禁通过 → 进入匹配（F008）。

## 4. 数据对象

### 4.1 公告/招标文件原文（Material 视图 + raw 存储层扩展）

> **字段对齐（2026-08-26，R004 定稿）**：原文对象的治理字段直接采用 **Material 15 字段契约**（F003 §4.1 / schema §13.1，冻结于 R003），本规格不重复定义；旧 draft 的 `raw_id`/`doc_type` 并入 `material_id`/`material_type`，差异登记见下方扩展字段表。**修改 Material 字段必须走 F003/schema 变更流程，禁止在本规格另立字段。**

**Material 字段（引用 F003 §4.1，不重复定义）**：

| 字段 | key | 说明 |
|---|---|---|
| 材料ID | `material_id` | 主键，前缀 MAT-PUB-（公开）如 `MAT-PUB-20260826-001` |
| 材料类型 | `material_type` | announcement / tender_document |
| 来源类型 | `source_type` | official_platform / agency / manual_entry 等（枚举见 F003） |
| 归属类型 | `owner_type` | 公开原文 = public |
| 密级/权限 | `classification` / `permission_scope` | 公开原文 = public / public_read（F003 §6.2 矩阵） |
| 原文哈希 | `content_hash` | SHA-256，防篡改 |
| 版本 | `version` | 从 1 递增，不覆盖历史 |
| 导入时间 | `imported_at` | |
| 解析状态 | `parse_status` | pending / parsed / partial / failed / manual_review |
| 数据责任人 | `data_owner` | |
| 其他 | `valid_until` / `evidence_refs` / `verified_at` / `status` | 公开原文一般置空/默认，见 F003 |

**raw 存储层扩展字段（本规格登记，不在 Material 契约内）**：

| 字段 | key | 说明 |
|---|---|---|
| 原文内容 | `content` | 不可变；URL 抓取正文或粘贴正文或上传文件全文提取 |
| 来源链接 | `source_links[]`、`source_platform` | 每链接可点击；`source_platform` 引用 `docs/合规数据源清单.md` 平台 |
| 采集模式 | `collect_mode` | manual_trigger（测试期）/ scheduled（正式期，未启用） |
| 存储定位 | `raw_storage_path` | `raw/` 下不可变目录 |
| 项目挂接 | `project_id` | 公告变更/澄清挂接（schema §7.4） |

**差异登记（v1.0 → v1.1）**：旧 draft 字段 `raw_id`→并入 `material_id`；`doc_type`→并入 `material_type`；`source_links[]/source_platform`→保留为 raw 存储层扩展字段（与 Material 契约无冲突，不入 F003）；`collect_mode`→raw 存储层扩展字段。`content_hash` 计算口径 = `content` 原文 SHA-256，版本递增时重新计算。

### 4.2 解析产物（待 R005 定稿）

- 项目主卡（`T-CARD-*`）：字段见旧 PRD §6.1 + F005。
- 事实子卡：basic / time / qualification / scoring / amount / compliance / requirement / checklist（既有）+ advantage（正式启用，见 F005）。
- 字段级引用：`clause`（条款号）+ `source_link` + 原文摘录（逐字）。

## 5. 输入/输出与证据要求

- 输入：公告 URL/正文、招标文件 docx/pdf。
- 输出：raw 原文（不可变 Material）+ 主卡 + 子卡 + 字段级引用。
- 证据要求：每个非空字段必须绑定来源链接与原文摘录；缺失标"待补"。
- **本次冻结范围**：入库输出 = Material 记录（4.1）+ 原文哈希 + 版本历史；主卡/子卡/字段级引用输出随 R005。

## 6. 业务规则

1. **测试期仅 manual_trigger**：人工粘贴/上传/单条 URL；scheduled 待 P0 验收（≥10 条真实公告）+ 法务《数据来源合规清单》签字后切换（旧 PRD §5.4；schema §5.1）。
2. **采集红线**（单一事实源 = schema §5.1-5.6 与 ADR-003）：保留 manual_trigger、限频、不绕过技术保护、不抓登录/付费/非公开内容、透明身份标识与个人信息最小化（30 天脱敏）。正式生产限频固定为**单源 ≤1 次/5 分钟、全平台 ≤200 次/小时**；staging/development 的较宽策略只用于本地调试/验收，不得解释为生产放宽。robots 必须在抓取前预检并留痕（`allowed`/`disallowed`/`missing`/`unreachable`），按 ADR-003 不由运行时预检自动阻断；是否启用某源仍以数据源清单登记为准。
3. **采集策略分级**：策略从 `runtime/config/collection_policy.yml` 读取，未知策略、缺字段或非法值 fail-closed。`production` 使用正式红线；`staging` 仅验收使用（单源 30 秒、全平台 500 次/小时、最多 5 页）；`development` 仅本地开发（关闭限频/robots、最多 5 页）；`mock` 仅 fixture。所有环境仍只支持 `manual_trigger`，不得通过环境变量启用 scheduled。
4. **列表分页**：同一次搜索任务按“源级抓取批次”处理。页数为 `min(policy.max_pages, source.max_pages)`；源未配置已验证的分页形态时只抓首页。分页 URL 必须保留既有关键词检索参数，页码从 1 开始；各页解析结果按公告 URL 去重后再做确定性关键词过滤。分页循环不得绕过限频：同一源同一搜索批次只产生一次源级限频事件，后续页不重复计数；摘要如实返回 `pages_requested` 与 `pages_fetched`。注册表的 `date_param` 仅为已验证平台日期过滤形态的预留字段；当前未完成平台实测，运行时不向平台提交日期过滤参数。
5. **地区字段分离**：平台 `region_scope` 只表达来源覆盖范围，不是公告项目实际地区。列表页未逐条给出项目地区时，候选 `region` 必须为 `null`/待核实；候选 DTO 可返回 `source_region_scope`、`region_inferred=false`、`region_provenance=source_scope_only` 供展示与审计，但不得将平台范围写入公告事实字段。
6. **数据源合规**：数据源清单以 `docs/合规数据源清单.md` 为运行视图、schema §1.4 平台注册表为唯一事实源；新增平台必须过法务审核，未审核不启用。
7. **公告版本不覆盖**：变更/澄清按 `project_id` 挂接（schema §7.4）；raw 不可覆盖（version 递增，schema §13.3）。
8. **去重**：L1 精确 / L2 近似 / L3 合并（schema §7）。
9. 解析失败/部分解析 → 人工复核（manual_review），不得静默跳过，不得编造（解析契约随 R005）。
10. 门禁：G0-G4 沿用既有；解析产物须过 G2（事实卡门禁）。

## 7. 失败/空态/异常状态

| 状态 | 处置 |
|---|---|
| 解析失败（版式不支持、加密 PDF、图片型 PDF） | manual_review + 提示人工处理 |
| 部分解析 | 已解析字段保留并溯源，未解析字段标"待补" |
| 权限不足（上传者非数据管理员） | 拒绝 + 审计 |
| 原文哈希不一致 | 阻断 + 告警（F003 §7） |
| 截止时间已过 | 既有规则：不入日报、标注已截止（schema §10） |
| 数据源未过法务审核 | 拒绝入库 + 提示走合规流程 |

## 8. API 目标态契约

```text
POST   /api/v1/intake/announcement/search # 测试期手动搜索，返回结构化公告事实卡和 project_id
POST   /api/v1/intake/announcement        # 单条 URL/正文入库；搜索推送仍仅 manual_trigger
POST   /api/v1/intake/tender-document     # 人工选择深入后上传完整招标文件（multipart）
POST   /api/v1/intake/{raw_id}/reparse    # 重新解析（人工复核后）
GET    /api/v1/intake/{raw_id}            # 原文 + 解析产物 + 引用
POST   /api/v1/intake/{raw_id}/confirm    # 人工确认通过门禁

前端联通约束：结构化公告推送只创建 `project_id` 和公告事实 Material，不触发解析、匹配或准入；只有绑定该 `project_id` 的完整招标文件上传并解析确认后，才进入 F005/F008 的要求拆分和自动匹配。
```

> 目标态草案（Iteration 3 冻结最终契约，同 F003 §8）；`{raw_id}` 路径参数在实现时以 `material_id` 对齐。

## 9. 权限、数据隔离、审计和合规

- 公开原文：public_read；上传动作记录审计。
- 招标文件若含企业私有信息（如标书），按 enterprise 密级处理（F003）。
- 个人信息：最小化、30 天后脱敏（schema §5.4 红线 R4）。

## 10. 验收标准与测试计划

**契约验收（2026-08-26，R004 定稿完成）**：

- ①合规数据源清单建立（引用 schema §1.4 注册表，审核状态如实登记）；
- ②原文对象字段与 Material 15 字段契约对齐（§4.1），扩展字段差异登记无冲突；
- ③不可变规则（version 递增 + content_hash）冻结；
- ④采集红线（robots/限频/UA/manual_trigger）单一事实源指向 schema §5；
- ⑤无 scheduled 采集（契约层面，运行时见下）。

**运行时验收（Iteration 2 原型执行，R004 标 done 的前置）**：

- ①手动触发可入库一条真实公告/招标文件并生成 Material 记录；
- ②原文不可变（hash 校验，篡改阻断）；
- ③限频与 robots 校验生效；
- ④解析失败正确进入人工复核（解析链路随 R005）；
- ⑤无 scheduled 采集入口。

**测试计划**：真实样例（康保储能EPC、广宗葫芦中学、阜平县高铁片区管网项目）试解析；限频/robots 校验；版本与去重用例——随 Iteration 2 原型与 Iteration 4 薄切片执行。
