# F024-结果产出、审批与审计运行时

- **需求来源**：R024 ｜ **状态**：定稿草案 v1.2（2026-08-31）
- **关联**：F008-F010、F019、F020、F023、ADR-001

## 1. 目标

将匹配运行结果输出为可查看、可导出、可审计的业务结果，并把已有审批函数接入持久化 API；将 F010 静态原型收敛为调用真实 API 的最小操作界面。结果系统只能将满分项目送入人工审批，不能自动投标、报价或签章。

## 2. 结果产出

每次匹配运行生成：

- 项目/文件/规则/证据版本摘要；
- 三类要求矩阵及条款、证据、判定原因；
- 四类独立结论、coverage、阻断/待补/复核队列；
- 准入状态及下一步责任人；
- JSON 机器可读快照和 HTML 人工核验报告。

导出必须标注 `as_of`、运行时间、引擎/规则版本、是否诊断模式。报告不使用“系统建议投标”“必然中标”等措辞。

## 3. 最小真实操作界面

复用 F010 的页面结构，但移除 `prototype/data.js` 硬编码数据：

1. 搜索/推送页调用 F020 公告搜索接口，展示 `job_id`、结构化事实卡和 `project_id`；该步骤不创建解析或匹配任务。
2. 选择与解析页调用招标文件入库接口，展示 `job_id`、任务状态和失败原因，并轮询至 `succeeded/manual_review/failed`；未上传完整文件不得开始解析。
3. 解析确认成功后，后端自动触发一次匹配；自动匹配页和风险页分别读取主卡/条款/字段引用、最新 `match_run`、coverage、阻断和待补原因，前端不提供项目内资料选择或首次匹配按钮。
4. 人工补录页通过材料创建/版本核验接口提交缺失材料；核验通过后调用重算，结果页刷新到新 `result_id`，旧结果标记 `stale`。
5. 审批页仅在后端返回 `internal_admission_eligible=true` 时显示审批操作；前端隐藏不能替代后端鉴权。队列和审计页支持按项目、状态、责任人筛选，显示 `request_id`/`result_id` 便于追踪。

## 4. 审批操作

1. `create_approval` 仅接受最新、完整且 `internal_admission_eligible=true` 的结果。
2. 经营负责人查看规则和证据链后批准或驳回；驳回 `comment` 必填。
3. 豁免必须记录授权人、原因、证据引用、有效期、覆盖项和审批时间；豁免不改变满分定义。
4. 豁免到期时任务将状态变为 `blocked_waiver_expired`；所有终态禁止重复决策。
5. 所有读取受 F003 权限矩阵控制，审批/豁免/导出均追加审计事件。

## 5. 审计与导出

审计记录至少包含 actor、at、action、basis、outcome、object_ref、request_id。仅允许追加；审计导出按项目、时间和动作筛选，审批人可导出 JSON/CSV。敏感个人信息按角色脱敏。

## 6. 农大验收路径

- 当前真实农大资料缺 NQ-H-007，输出应为待补/阻断，**不得出现审批入口**。
- 补齐并经核验后重跑，才可构造真实 `pending_bid_approval`。
- 审批通过仅得到 `approved_for_bidding`，仍不产生递交、报价、签章或投标平台动作。

## 7. 验收与测试

- 结果 JSON/HTML 与数据库同一 `result_id` 快照一致。
- 浏览器从上传到结果页全程使用真实 API，无硬编码农大结果；刷新页面后任务和结果仍可恢复。
- 浏览器联通顺序必须可验证：搜索推送 → 选择项目并上传完整文件 → 解析成功自动匹配一次 → 风险/缺失只读展示 → 补录核验后重算 → 人工审核；任何 GET 结果接口不得触发匹配。
- 非满分创建审批返回业务错误并记录审计；驳回空意见、无证据豁免、过期豁免均被拒或回阻断。
- 审批、驳回、豁免、过期和导出均可由集成测试复现。
- 接口清单中不存在自动投标、报价计算推荐或签章动作。
