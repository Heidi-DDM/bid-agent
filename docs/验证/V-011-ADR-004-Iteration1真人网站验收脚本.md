# V-011：ADR-004 Iteration 1 真人网站验收脚本

> 版本：v1.0 ｜ 建立：2026-09-17 ｜ 适用：发布 `0017_adr004_iteration1_workflow` 后的演示/生产候选环境  
> 验收性质：真人实操验收脚本，不替代代码审查、自动化测试、数据库备份或变更审批。  
> 保密：本文**不记录账号、口令、令牌、Cookie、企业私有材料内容或原始招标文件**。证据和截图使用脱敏项目编号/缺陷编号保存。

## 1. 前置条件与停止条件

1. 发布前已完成已批准版本备份；执行 `alembic upgrade head` 后应显示 `0017_adr004_iteration1_workflow (head)`；API 与**唯一 worker**均已重启。
2. 在运维窗口检查 `/healthz` 和 `/readyz`：整体可用，`checks.worker.available=true`；记录时间和响应中的 request_id（如有），不在报告粘贴令牌或连接串。
3. 准备至少三类**脱敏、未过截止**项目：
   - A：身份 `identity_warning`；
   - B：有缺证、人工复核和明确不满足项；
   - C：有足够已核验材料、可走完整正式匹配的对照项目。
4. 测试人员：投标专员、数据管理员、经营负责人、法务（角色与实际权限一致）。不得共用帐号串改角色，不得以数据库直改绕开接口门禁。
5. 以下任一情况立即停止该用例，登记缺陷并不以手工数据库改数“通过”：迁移不是 head、worker 不可用、出现私有证据越权可见、过期/身份冲突可绕过、系统出现自动投标/报价/签章/递交承诺。

## 3. 用例清单

| 编号 | 操作 | 预期与合格判定 |
|---|---|---|
| V011-01 | 以投标专员登录，进入项目工作台。 | 显示项目阶段、身份、截止事实、正式匹配门禁、开放任务数、准备立项状态及服务端阻断原因；页面不显示“推荐投标”“可投标”“中标概率”“自动报价/递交”等结论或操作。 |
| V011-02 | 对项目 A 执行“快速预核”，再刷新页面和正式审批页。 | 结果只分“已登记事实、待补、待核实/风险类型”，带“不是投标建议、不是正式匹配、不能替代正式审批”声明；不新建正式匹配、不改变项目准入状态、不创建正式审批。 |
| V011-03 | 项目 A 在 `identity_warning` 下，以投标专员发起正式匹配/重算。 | 服务端返回 409，原因是 `identity_warning`，并可记录 request_id；前端禁用不构成通过依据。 |
| V011-04 | 投标专员或经营负责人在身份核对页面填写具体核对依据，执行 `identity-confirm`；重新发起正式匹配。 | 身份变为已确认后才允许创建正式匹配任务。确认说明有审计留痕。不得通过空说明、普通角色或只改前端状态解除。 |
| V011-05 | 对身份 `identity_conflict` 项目重复 V011-03/04。 | 冲突仍阻断匹配/重算和正式审批；不能用 `identity-confirm` 直接洗白，必须先纠正两侧事实并重新校验。 |
| V011-06 | 以经营负责人在未过期项目创建投标准备立项，填写理由；分别批准、拒绝各演练一次。 | 仅经营负责人可操作；理由和决定意见必填并审计。文案只能表达“允许/不允许投入准备工作”，明确不等于投标、报价、签章或递交；不改变正式准入资格、不绕过满分门禁。 |
| V011-07 | 在已过截止项目创建或批准准备立项，并发起匹配、重算、正式审批。 | 各正式入口均被服务端阻断；不得仅凭日期/前端显示绕过精确截止。 |
| V011-08 | 对项目 B 完成一次正式匹配，打开任务中心。 | 缺证生成 `evidence_supplement`，明确不满足生成 `termination_correction`，规则/文件/身份/资源问题映射到相应任务类型；任务有来源、条款/要求引用、责任角色、关闭条件和审计。重复读取/同一结果同步不产生重复任务。 |
| V011-09 | 数据管理员领取“资料补证”任务，提交一个或多个可追溯证据引用。 | 状态仅进入“已提交证据，待核验与重算”；页面和接口均不得把此操作显示为“满足/关闭”。投标专员与法务只见证据数量/已提交状态，不得见具体企业私有证据引用。 |
| V011-09A | 在项目工作台点“提交证据引用”或“提交处置结论”；分别验证空提交、取消、Escape、重复点击、成功提交。 | 使用页面内弹窗而非浏览器 `prompt()`；证据引用支持逐行或中英文逗号分隔并去重；空提交有页面内提示，取消/Escape 不产生请求，提交中不可重复提交；成功显示 `request_id` 并刷新任务。页面明确禁止粘贴企业私有材料正文，补证或处置结论均只显示“待核验与重算”，不得显示为满足/关闭。 |
| V011-10 | 尝试对 `termination_correction` 使用补证接口；尝试由无责任角色用户领取、转派、提交或处理任务。 | 前者拒绝，明确不满足不能用补证洗白；后者返回 403/状态错误，不能因责任人名称相同而绕过角色授权。 |
| V011-11 | 投标专员/责任角色为非补证任务提交处置结论，再发起受门禁保护的重算。 | 任务保持“待核验与重算”，不是人工自行关闭。只有**新**正式匹配结果已不再出现同一来源问题，系统才自动关闭；同一问题再次出现时任务应可审计地重新打开。 |
| V011-12 | 对项目 C 完成匹配并尝试创建正式审批。 | 仅最新、完整、满足内部准入且证据回链完整的结果可创建 `pending_bid_approval`；缺证、人工复核、明确不满足、过期、身份问题和陈旧结果均不能绕过。即使进入审批，也必须由经营负责人决定，系统不自动投标。 |

## 4. 发布后结论

- 全部关键用例（V011-01～V011-12，含 V011-09A）通过，且无停止条件命中：可提交“生产候选验收通过”给业务、资料、投标、法务、运维联合签署；这不等于自动授权真实投标。
- 任一关键门禁、越权泄露或自动决策问题失败：结论为“不通过”，停止扩大使用范围；回滚至经批准版本或修复后重新全量验收。
