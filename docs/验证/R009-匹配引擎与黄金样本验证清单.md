## 1. 目的与边界

本清单用于证明“规则声明、实际执行和报告结论”一致。它不替代经营部的投标决定，也不将系统结果描述为法律资格结论、评标委员会得分或投标建议。

企业资料、招标原文、证据快照和运行结果属于受限数据，不提交 Git。Git 仅保存脱敏规则、测试代码、验证方法、哈希和不含敏感内容的验收结论。

## 2. 通过口径

一次黄金样本验证只有同时满足以下条件才可标记为“通过”：

1. 规则文件经结构校验，Requirement ID 唯一，声明条数与诊断模式执行条数相同。
2. 每一条结论都具备条款引用、证据引用、`as_of`、规则版本与判定理由。
3. 证据在条款时点已签发/生效、已核验且有效；否则结论为 `unverifiable`，不得判为满足。
4. 投标专员逐条确认条款拆分和预期结果；数据管理员确认企业证据可用性与时点。
5. 自动化回归、黄金规则入口和 CI 均通过；失败项已修复并重跑。

任何一项不满足，样本状态只能为“待补”“待复核”或“失败”，不得写“匹配完成”。

## 5. 执行与留痕

本地和 CI 均运行下列命令：

```bash
python -m unittest discover -s scripts/tests -v
python scripts/matching/run_golden_lab.py
```

项目本地环境使用 `.venv`，依赖从 `requirements-dev.txt` 安装。每次真实样本重跑必须登记：规则文件 commit、招标文件/证据快照 hash、`as_of`、执行命令、运行时间、执行人和输出摘要。报告只能引用同次运行结果；规则、证据或原文版本变化后，旧结果标记为 `stale` 并重新验证。

## 6. 退出条件与后续

- V-001 至 V-006 是开始原型前必须完成的最小验证包；未完成时原型只可使用明确标注的模拟数据。
- V-007 至 V-010 是 R009 从 `in_progress` 进入验收评审的条件；任何未决项保持 `in_progress`。
- 原型可以在 V-001 至 V-006 通过后开始，但不得把原型展示结果当作真实项目匹配验收。
