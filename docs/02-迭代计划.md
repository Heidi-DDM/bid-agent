# 02-迭代计划

> 建立：2026-08-25 ｜ 路线依据：ADR-001/ADR-002 与最小验证闭环 ｜ 业务验证顺序固定：Iteration 0 → 5 → 后续；运行时开发在 Iteration 3 契约冻结后按 R018→R019→R020→R025→R021→R022→R023→R024 顺序推进，不允许跳过数据、权限和知识库基础。
> 每迭代包含：目标、范围、非目标、输入、输出、依赖、验收标准、风险、退出条件。

> **交付校准（2026-09-02）**：Iteration 4 的目标是 D1 农大演示薄切片，预计 6-8 周；D2 受限生产试用需在 Iteration 4 后追加 4-6 周的认证、部署、备份恢复、监控和客户验收；D3 规模化验证再追加 4-8 周。原“4-5 周 M1、7-9 周 M2”仅可作为不含生产门槛的乐观开发值，不作为客户承诺。

## Iteration 0：文档体系与基线盘点

- **目标**：建立文档体系与决策记录，盘点真实案例与待确认项，明确范围变化。
- **范围**：AGENTS.md、docs/ 全套（规则/需求池/迭代计划/功能规格占位/修改日志/现状/ADR-001/archive）；真实案例盘点（康保储能EPC、广宗葫芦中学、阜平县高铁片区管网等候选）；风险与待确认清单（见 `docs/05-项目现状.md` §5）。
- **非目标**：不写业务代码；不动旧 PRD；不采集新数据；不设计 Schema 细节。
- **输入**：旧 PRD v1.0/v1.1、智库复用方案 v1、schema/ 现状、目录盘点。
- **输出**：完整文档体系；ADR-001；案例候选清单；待确认事项清单。
- **依赖**：无（但公司需尽快确认待确认事项以解锁 Iteration 2 的原型设计）。
- **验收标准**：①文档目录齐全，Git 可提交；②ADR-001 覆盖范围变化、四层职责、状态机、满分定义；③案例候选与待确认清单存在。
- **风险**：名称不一致（某建设 vs 某建投）影响对外材料；文档体系无人维护。
- **退出条件**：ADR-001 评审通过；待确认清单完成首轮确认。

## Iteration 1：数据治理契约与 Schema 冻结

- **目标**：冻结最小数据治理契约与招投标 Schema（含新增资格/资源核查域）。
- **范围**：Material 契约（source_type/owner_type/classification/permission_scope、hash、版本、有效期、解析状态）；骨架树审计与扩展（新增匹配/项目经理/准入节点）；主卡/子卡字段冻结；公告/招标文件入库与解析规则（人工粘贴、上传、单条 URL）。
- **非目标**：不实现匹配/评分逻辑；不建设私有资料库；不开发界面。
- **输入**：ADR-001、旧骨架树、PRD §六 字段、真实公告/招标文件样例（人工粘贴或脱敏）。
- **输出**：F003 契约冻结；Schema v1 审计通过并激活；F002/F004/F005 规格定稿。
- **依赖**：Iteration 0；公司确认评分规则边界（可先冻结数据结构，规则值可后续配置）。
- **验收标准**：①Material 契约字段全冻结；②schema 审计 coverage 100% 无冲突；③字段级溯源规则明确；④解析失败/部分解析处置明确。
- **风险**：字段冻结过早导致返工；企业资料口径未确认导致字段设计偏离。
- **退出条件**：字段与契约经评审冻结，进入原型设计。

## Iteration 2：真实案例原型

- **目标**：用真实/脱敏案例做出可点击原型，覆盖最小闭环全部界面。
- **范围**：原型主流程（搜索与结构化推送、选择深入与完整文件解析、解析结果与自动匹配、风险/缺失、人工补录、人工审核/审计）及异常态；企业资料页仅作为后台状态页，原型数据使用脱敏真实案例。
- **非目标**：不开发真实前后端；不做真实计算引擎；不做权限系统实现。
- **输入**：Iteration 1 冻结字段；真实案例资料（脱敏）；企业资料样例（脱敏）。
- **输出**：可点击原型 + 使用说明 + 数据样例。
- **依赖**：Iteration 1；公司确认原型数据可脱敏使用。
- **验收标准**：①首页可生成结构化公告推送；②未上传完整招标文件不得解析；③解析完成自动匹配一次；④风险/缺失可进入人工补录并重算后提交人工审核；⑤覆盖 5 类异常态；⑥原型可点击走通最小闭环。
- **风险**：原型过度设计；脱敏数据不足。
- **退出条件**：原型可演示，进入用户验证。

## Iteration 3：用户访谈与契约冻结

- **目标**：投标专员/经营负责人验证流程与评分规则，冻结状态机、API 和权限契约，并完成后续运行时开发所需的技术基线、数据库和 API/权限实施准备。
- **范围**：≥3 场用户验证（流程、评分规则、字段、队列、审批）；依据反馈修订原型与规格；冻结准入状态机、四层权限矩阵、API 目标态契约；按 F018-F020 建立可重复启动环境、数据库迁移/备份方案、任务模型、RBAC 和接口骨架；按 F025 冻结三层知识库、混合检索、权限过滤、模型出域和候选证据契约。
- **非目标**：契约冻结前不编写业务运行时代码；本迭代不接入真实模型分析、不跑完整农大链路，不扩大范围到编标/报价。
- **输入**：Iteration 2 原型；用户清单（投标专员、经营负责人、数据管理员）。
- **输出**：验证报告（含修改点）；冻结的状态机/API/权限契约；F008/F009/F010/F025 定稿；F018-F020 的部署、迁移、权限和接口验收记录；R025 索引与黄金检索集方案。
- **依赖**：Iteration 2。
- **验收标准**：①用户确认"满分定义"与三类要求划分；②状态机无未定义迁移；③API 契约覆盖全部页面动作；④权限矩阵覆盖公开/私有/审批三层；⑤F025 的层级、过滤字段、候选证据边界和出域开关完成评审。
- **风险**：审批人缺位导致契约无法确认；评分规则争议。
- **退出条件**：契约冻结；R018-R020 的启动、迁移、健康检查、权限和幂等性验收通过；R025 的知识库数据模型、索引幂等和检索负例方案通过评审，进入农大运行时链路开发。

## Iteration 4：端到端薄切片（D1，预计 6-8 周）

- **目标**：先完成 R021-R024 运行时能力，再只开发一条以河北农业大学东校区研究生宿舍建设项目施工（简称“农大”）为唯一试点的端到端薄切片。
- **范围**：按 R025→R021→R022→R023→R024 顺序实现：原文入库（不可变）→ 三层知识库分片/索引 → 解析/模型抽取（主卡/三类要求）→ 企业资料导入与 OCR 核验（后台持续维护）→ 受权限和 `as_of` 过滤的混合检索 → 解析成功自动匹配当前有效资料 → 结构化核验/匹配矩阵与风险/缺失 → 人工补录/核验后重算 → 人工审核/驳回/豁免 + 审计；只使用农大真实/脱敏资料，不把博野作为运行时试点。
- **非目标**：批量采集、定时调度、日报推送、全网监控、自动投标/报价、完整标书、竞对情报、成本测算。
- **输入**：Iteration 3 冻结契约与 R018-R020 运行时基础；农大招标文件/澄清版本；农大最小私有资料样本。
- **输出**：R021-R024 运行时验收记录；农大可运行薄切片 + 演示脚本 + 已知限制清单。
- **依赖**：Iteration 3；R018-R020 通过退出验收。
- **验收标准**：①农大端到端跑通（含单条手动搜索/结构化推送）；②20 条农大规则全量覆盖并保存版本/证据快照；③L2 Recall@5≥0.90、L3 Recall@10≥0.90、数字/日期/等级 exact match≥0.95；④权限泄漏率 0、引用完整率 100%；⑤状态机迁移与契约一致；⑥审计记录完整；⑦NQ-H-007 等缺失证据保持 blocked_missing_data，不得人为补齐；⑧无自动投标动作。
- **风险**：解析质量不足（docx/pdf 版式多样）；资料库数据质量差。
- **退出条件**：薄切片通过演示验收。

详细技术任务、前置确认和证据化验收项见 `docs/08-开发执行与验收清单.md`。

## Iteration 5：三项目价值与质量验证（D3 前置，D2 后 4-8 周）

- **目标**：用 ≥3 个真实/脱敏项目验证耗时、检索召回、结构化准确性、人工修改和漏项发现率。
- **范围**：3 个项目跑通全流程；对比人工复核结论；量化指标（处理耗时、L2/L3 Recall、数字字段 exact match、匹配准确率、人工修改率、漏项发现率）；形成质量报告并闭环到规则/Schema/索引配置。
- **非目标**：不做规模化推广；不进入正式期 scheduled。
- **输入**：Iteration 4 薄切片；3 个真实/脱敏项目。
- **输出**：量化验证报告；规则/Schema 修订项；P0 验收结论。
- **依赖**：Iteration 4。
- **验收标准**：①样本 ≥3；②检索、结构化、匹配和效率指标可量化可复现；③权限负例和版本重放通过；④漏项/误判有根因分析与修复项。
- **风险**：样本不足或数据敏感无法脱敏。
- **退出条件**：报告通过经营负责人评审。

## 后续（Post-Iteration 5）

- 批量采集（R014）：指定来源批量采集、日报推送、反馈校准。
- 定时调度（R015）：scheduled 模式（切换门槛：P0 验收 + 法务《数据来源合规清单》签字）、失败熔断、归档、月度校准。
- 私有库扩容（R006/R007 扩展）：更多资质/业绩/人员字段与历史数据迁移。
- 辅助编标（R016）：单独立项，独立于准入链路。
- **非目标（永久）**：自动投标、自动报价、自动签章、无证据 AI 判断、竞对非公开情报、成本测算与中标概率预测、未经授权私有数据接入、以"模型认为适合"代替规则与证据。

## 风险登记（全局）

| 风险 | 等级 | 对策 |
|---|---|---|
| 评分规则/满分定义依赖公司确认，确认延迟阻塞 Iteration 3 | 高 | Iteration 1 只冻结结构，规则值配置化，可后补 |
| 企业私有资料质量差（清单未完善）导致匹配不可判定 | 高 | 缺失即阻断+待补队列，不推断；先以脱敏样例验证 |
| 招标文件解析（docx/pdf 版式多样）准确率不足 | 中 | Iteration 4 薄切片限定文件类型与样例；解析失败进人工复核 |
| RAG 召回或向量索引被误当成事实/判定 | 高 | RAG 仅返回候选证据；混合检索和权限过滤；结构化字段与确定性规则引擎判定；Recall/exact-match 和引用完整率门禁 |
| 项目经理数据（在建状态/有效期）维护滞后 | 中 | 数据责任人制 + 有效期校验 + pending_verification 状态 |
| 合规风险（采集/个人信息） | 高 | 红线清单 + L0-L3 + 法务签字门槛（既有资产，保留） |
| 范围蔓延（把批量/推送/编标提前） | 高 | 需求池 P0/P1/后置硬约束；薄切片明确非目标清单 |
