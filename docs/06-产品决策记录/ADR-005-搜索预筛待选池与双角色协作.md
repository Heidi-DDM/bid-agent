# ADR-005：搜索预筛、待选池、双角色协作与复核闭环

- **状态**：已接受
- **日期**：2026-09-21
- **关联**：ADR-001、F020、F022、F023、F024

## 决策

1. 搜索结果在进入人工工作台前，必须经过**确定性预筛**：先按公告类型及经营负责人维护的行业/排除关键词标注；仅将明确命中非招标公告类型的条目自动排除。标题或列表页事实不足时标为“待人工查看”，不得以模型推断为“不感兴趣”或“可投”。
2. 每次搜索的新增候选都同步到统一**待选池**。待选池保留候选原始链接、来源、搜索批次和预筛规则版本；同一项目的新公告可替换仍待处理的旧候选，已选择深入、已导入及人工删除的记录不得被自动覆盖。人工可选择深入或软删除；软删除保留审计与事实链。
3. 待选池的展示单元为“搜索简报”：只陈列标题、来源、发布日期、确定性预筛命中、待补字段与操作入口；它不是投标建议、资格判断或审批结论。
4. 定时/人工搜索的触发方式由 `COLLECTION_POLICY` 配置控制，而不再作为 API 或 Schema 硬编码红线；仍必须遵守 AGENTS.md 规定的两条采集底线。
5. 角色收敛为两级：**投标专员（含其 Agent）**负责搜索、材料维护、解析复核、匹配和处置；**经营负责人**拥有全部查看、规则管理、管理面板与最终审批/豁免权。历史 `data_admin`、`legal` 登录角色仅作为兼容别名映射至投标专员，不再是可配置业务角色。
6. 企业资料补录后，必须先经过证据核验，再以证据版本显式触发受影响项目重匹配；系统不得因上传或模型推断直接将硬性条件改为满足。
7. 匹配结果的“建议”统一改为**下一步处置**：按 `blocked_missing_data`、`blocked_hard_requirement`、待人工复核、满分待审批等可追溯状态输出，不输出“建议投标/不投标”。

## 后果与边界

- 预筛规则是版本化、可审计的组织策略；规则变更仅影响后续预筛，不篡改历史简报。
- 公开情报层仍只保存原文事实；预筛的命中词、规则版本和排除原因是规则执行记录，不是对项目价值的判断。
- 管理面板只聚合项目状态、待办与阻塞环节；经营负责人仍需人工完成审批，满分不会自动投标。
