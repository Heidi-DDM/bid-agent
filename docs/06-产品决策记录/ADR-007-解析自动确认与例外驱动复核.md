# ADR-007：解析自动确认与例外驱动复核（隐藏解析，直达风险判定）

- 日期：2026-09-25
- 状态：已接受（业主 2026-09-25 拍板"认可，请开始执行"）
- 关联：ADR-001（投标准入边界/满分定义）、ADR-004（分阶段与证据链）、F005 §8（人工决策留痕）、F008 §4.1（as_of）、F021 §2（解析运行时）、F023 §2（匹配与准入）

## 1. 背景与问题

业主实测（2026-09-24 邢台 115 页文件）反馈：招标文件本身分门别类写得清楚，但系统要求招标人员逐条复核几十条解析候选（47 条），
比直接读招标文件更费力——**本末倒置**。现流程"上传 → 解析 → 人工逐条复核确认 → 匹配 → 风险判定"中，
"人工复核全部解析候选"这一步对高置信项（确定性锚点逐字命中原文、带页码可回跳，约占 70-80%）是重复劳动。

## 2. 决策

**解析复核从主流程中移除，改为例外驱动（review by exception）**：

1. **系统自动确认**：解析完成后，worker 对满足全部以下条件的候选自动写"通过"
   （reviewer=`system.parse_auto`，审计事件留痕，人工可随时改判——决策接口不区分系统/人）：
   - 仍是 pending；
   - 已定位（非 missing，assertion/value 非空）；
   - 置信度 high/medium；
   - **确定性锚点命中**（`rule.located_by != "llm"`——模型定位/发现项永不自动确认，P4 契约不变）。
   适用于规则候选、主卡字段、商务条款三类。
2. **例外式规则集**：规则集允许带待确认例外生成——`confirm_rules_from_approved(allow_pending_exceptions=True)`
   从已确认子集写 Requirement；pending 行记入 `RuleSet.snapshot.pending_exceptions[]`（不写 Requirement，不推断）。
   as_of 取值链沿用 F021 §2.3（自动路径通常取自自动确认的主卡 deadline_bid；取不到 → 不自动生成规则集，退人工确认）。
3. **解析完自动触发索引+匹配**（复用 `schedule_post_parse`：规则集存在即触发首次匹配）。
   用户上传文件后**直接看到风险评分与条件符合判定**；待确认项在风险页（矩阵）顶部呈现，逐条处置。
4. **例外清零自动重确认**：最后一个待确认项被决策后，自动生成**规则集快照链**新节点
   （`RS-<材料>-v<版本>-r2/r3…`，历史快照不可覆盖不变），既有 Requirement 复制入新快照（id 追加 `-r2` 后缀，旧 id 与历史匹配结果不受影响），
   新决策项写入，not_applicable 并入快照；随后自动触发匹配重算。
5. **满分门禁**：存在待确认例外时 `internal_admission_eligible=false`
   （匹配执行器在生成准入结果前检查 `parse_candidates` pending 数，写入 `coverage.parse_exceptions_pending`）——
   **未确认完不得满分**，满分才进投标审批的 ADR-001 底线不破。

## 3. 红线（不变的约束）

- 缺失候选（锚点未命中）**永不自动决策**——"本文件无此条款"是事实断言，必须人拍板（三选一语义不变）。
- 模型定位/发现候选（located_by=llm）**永不自动通过**——低置信产物必须人工确认（P4 不变量）。
- 人工已决策行永不覆盖（F005 §8）；系统自动确认留审计（`parse.auto_confirmed` 事件 + reviewer 标识）。
- 满分 ≠ 自动投标（ADR-001）；待确认例外阻断满分。
- 历史规则集快照不可覆盖：重确认生成新快照节点，不修改既有 RuleSet/Requirement 行。

## 4. 界面影响

- 主旅程变为：上传 → **风险与判定（矩阵页为落地页）** → 处理待确认项（如无则无此步） → 审批。
- 矩阵页新增"待确认项"区（红色横幅 + 逐条快捷处置：通过 / 本文件无此条款 / 跳复核页深度处理），
  清零后自动重算并提示。
- 复核页（queue.html）保留为后台/深度处理视图（步骤条更名"待确认与处置"），不再是主流程必经步骤。
- 解析复核页历史语义不变（审计可查每条候选谁确认的：人 or system.parse_auto）。

## 5. 后果与风险

- 模型定位项的错报会出现在风险页——但它标"待确认"、不参与满分判定、逐字校验+强词分类已收敛，风险可控；
  召回语料（golden/parse_recall_cases.json）持续兜底。
- 规则集快照链使 requirement_id 在重确认后追加后缀——匹配结果跨快照的历史行引用旧 id，仍在库可查；
  解释链按 run_id 定位不受影响。
- 若 deadline_bid 未解析出（罕见），自动路径退化为人工确认（不推断 as_of，F008 §4.1 不变）。
