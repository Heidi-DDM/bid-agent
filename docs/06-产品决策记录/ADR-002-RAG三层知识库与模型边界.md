# ADR-002：RAG 三层知识库与模型边界

- **状态**：已接受（Accepted，待法务/IT/经营负责人评审）
- **日期**：2026-09-01
- **关联**：ADR-001、F003、F018-F025、R025

## 1. 背景

本期新增要求将 RAG 作为主要的信息资料库，覆盖：①联网检索到的可投标信息；②完整招标文件及其条款；③企业人员、业绩、证书、财务等私有资料。仅有向量存储会造成“召回结果被误当成判定”的风险；仅依赖 LLM 又无法保证金额、日期、等级和有效期的精确核验。

## 2. 决策

### 2.1 统一知识与证据库

采用 PostgreSQL + pgvector，逻辑分为：

```text
L1_public   公开可投标信息（公告、主卡、事实子卡）
L2_tender   招标文件知识（条款、评分、澄清、补遗）
L3_enterprise 企业能力与证据（资质、人员、业绩、证书、财务）
```

每个分片保留 Material、版本、内容哈希、项目/标段、页码/段落、权限、核验状态和索引版本。原文和结构化事实分别持久化；向量是可重建的检索索引，不是事实来源。

### 2.2 RAG 与规则引擎分工

```text
RAG 混合检索（关键词/BM25 + 向量 + metadata filter + reranker）
  → 候选条款/候选企业证据
  → 结构化字段、单位、日期、等级、有效期核验
  → F008/F023 确定性规则引擎
  → 四类结论与准入状态
```

RAG 只能返回 `candidate_only=true` 的证据候选；向量相似度、LLM 置信度和 reranker 分数不得进入准入公式。召回不到证据是 `unverifiable`/`blocked_missing_data`，不是自动“不满足”。

### 2.3 模型与出域

- DeepSeek API 仅处理 `permission_scope=public_read` 的公开资料，用于条款分类、字段归一化和规则草案。
- 企业 OCR、embedding 和可选 reranker 使用本地/内网模型；企业向量也属于敏感数据，按 L3 权限隔离。
- 任何模型不得生成企业不存在的资料、直接输出满足/不满足、投标建议、报价或审批决定。

### 2.4 权限与失效

检索前强制过滤权限、项目/标段、版本、`as_of` 和 `verification_status`；权限不明时 fail-closed。材料/证据新版本、澄清补遗或索引版本变化使旧 chunk 和 retrieval run `stale`，不得驱动审批。

## 3. 验收门槛

- 权限泄漏率 0，引用完整率 100%；每条候选可回链 Material/版本/哈希/页码。
- L2 条款 Recall@5 ≥ 0.90，L3 企业证据 Recall@10 ≥ 0.90。
- 数字/日期/等级 exact match ≥ 0.95；未达标进入人工复核。
- 索引和检索幂等、可重放；模型或 pgvector 不可用时原文仍可入库，任务进入可解释失败/复核状态。
- 农大 20 条要求均有条款候选；NQ-H-007 缺失时保持 `blocked_missing_data`，不得被语义相似证据放行。

## 4. 影响与未决事项

新增 R025/F025；F018-F024 增加索引、检索、快照和验收约束；F019 增加 `knowledge_data` 及三类表。正式环境的 embedding 模型、维度、分片参数、pgvector 扩展、外部 API 白名单和法务出域审批仍需确认。
