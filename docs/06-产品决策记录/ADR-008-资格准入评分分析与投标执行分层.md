# ADR-008：资格准入、评分分析与投标执行分层

- **状态**：提议（Proposed，待经营负责人、投标负责人和资料管理员评审；未实施、不替代既有冻结契约）→ **技术实施已落地（2026-09-28，见 §6）**：按 `docs/12-技术开发执行方案-匹配结果收敛与解析质量分层-20260928.md` 阶段 0-3 完成代码与测试；§4 所列业务参数的正式签字仍开放，签字前以上线灰度口径控制
- **日期**：2026-09-28
- **决策人**：基于投标专员对本机原型的走查反馈起草
- **关联**：ADR-001（投标准入边界）、ADR-004（投标准备与正式审批分阶段）、ADR-007（例外驱动复核）、F008、F020、F021、F023、`docs/12-技术开发执行方案-匹配结果收敛与解析质量分层-20260928.md`

## 1. 背景

ADR-007 已将解析候选的人工逐条复核移出主旅程；用户上传后直接看到条件符合判定和风险。但本机原型走查显示，当前结果页仍把四种语义不同的内容并置为同一种“匹配问题”：

1. 企业资格与资源是否能由已核验证据证明；
2. 评分规则是否可计算、企业在可计算项目上是否有得分机会；
3. 报名、保证金、递交、开标、踏勘等投标执行动作是否到时完成；
4. 模型未定位、低置信或尚未人工处置的解析质量例外。

这种并置会把“尚未开始递交”误读为“企业缺证”，也会把“模型未读到常见条款”误读为企业不符合条件；同时，若不同人员分别满足项目经理资格、B 证和在施限制，还可能形成没有真实候选人的拼接式满足结论。

### 1.1 本 ADR 不处理的事项：历史样本文件

当前测试没有现成的与待选项目一一对应的招标文件，因此允许使用企业已完成历史项目的招标文件作为**脱敏解析样本**。本次观察到的项目—文件名称/采购人/地点不一致由该测试安排造成，**不作为本轮产品缺陷、也不作为本 ADR 的优化项**。

该样本在界面和结果中应被明确标识为“历史解析样本／非当前项目文件”；其结果仅用于验证解析和匹配能力，不能解释为当前项目真实准入结论，更不能用于创建审批或递交。生产模式下文件—项目归属校验、ADR-004 的身份门禁仍然有效，本 ADR 不削弱该红线。

## 2. 拟议决策

### 2.1 结果分为四个互不替代的工作域

| 工作域 | 面向的问题 | 可影响的状态 | 不得混入 |
|---|---|---|---|
| 资格与资源核查 | 企业、资质、许可、人员、业绩、信用、财务等是否有同一时点的有效证据 | `qualification_result`、内部准入 | 模型漏读、尚未开始的投标动作 |
| 评分分析 | 哪些评分规则可自动复算、需人工评审或尚不可计算 | `scoring_result`、内部准入的评分条件 | 评标办法说明、报价推荐、评委实际打分 |
| 投标执行计划 | 到相应阶段应由谁完成报名、保证金、编制、递交、开标、踏勘及回执 | `operational_readiness`，仅在相应阶段形成门禁 | 企业资料缺失或资格不满足 |
| 解析质量与待确认项 | 条款未定位、低置信、冲突、规则未结构化或人工处置待办 | 解析质量状态、ADR-007 的满分阻断 | 企业“不满足”的事实结论 |

主结果页默认展示“资格与资源核查”，并只展示最多三项按风险排序的优先处理事项。解析质量使用摘要和可展开抽屉/独立视图呈现，不再以长列表占据匹配结论首屏。

### 2.2 准入与执行的门禁边界

1. 只有可比较的 `hard_requirement` 和已可计算/已完成内部评审的 `scored_requirement` 可参与“是否可送人工审批”的内部准入判定。
2. `action_requirement` 仍需保留原文、责任人、截止和回执；它们不再因 `not_started` 自动进入“缺证阻断”或“资格不满足”。
3. 动作仅在 `required_by_stage` 到达时参与该阶段的执行门禁：例如 `submission_ready` 在准备递交时检查，`opened` 在开标阶段检查。若原文明确把某动作作为审批前置条件，应以 `required_by_stage=approval_ready` 显式建模并保留条款证据。
4. **满分不等于自动投标**。即使资格和评分满足，仍仅可进入 `pending_bid_approval`；递交还须通过后续执行门禁和人工审批。

### 2.3 结果状态必须可解释、互斥到足以驱动处置

不得继续以“数量为 0 或证据缺失”合写同一结论。每个匹配项至少区分：

- `satisfied`：有足量、有效、已核验且可回链证据；
- `not_satisfied`：证据充分，明确显示数量不足、等级不够、超期、专业不符或事实冲突；
- `blocked_missing_data`：所需企业资料/证据不存在或尚未核验，不能据此断言不满足；
- `manual_review`：需要专业判断、规则未结构化、证据冲突或人员候选方案待选；
- `not_calculable`：仅适用于评分分析，公式、授权输入或评分所需证据不足；
- `not_started` / `ready` / `completed` / `overdue`：仅适用于投标执行动作；
- `parse_exception`：仅适用于解析质量，不能直接映射为企业匹配失败。

### 2.4 人员结论按同一候选方案闭环

对“项目经理资格、注册证、B 证、社保、在施状态、类似业绩”等具有人身关联的条款，匹配引擎须选定同一 `person_id` 后再计算满足情况；不得把多人各自的一项优势拼接为一个“满足”。

系统可给出多个“拟派班子方案”，但每个方案独立存储岗位—人员—证据绑定、有效时点及结论。项目经理为必需角色时，一个方案内必须由同一人覆盖所有该角色关联条件；技术负责人、安全员等亦按岗位约束独立绑定。

### 2.5 评分规则按可操作性分类

评分解析产物必须标注为以下之一：`objective_calculable`、`subjective_review`、`price_formula`、`methodology_only`、`unstructured`。

- 只有 `objective_calculable` 可展示“可复算得分”；
- `price_formula` 只展示规则和经授权录入的输入，系统不得生成、推荐或假定报价；
- `subjective_review` 只展示内部质量评审状态，不能伪称评委得分；
- `methodology_only`（如综合评估法、随机平均价、百分制说明）不计入“可复算 0/0”，应显示为“评标方法说明”；
- `unstructured` 明确显示“规则待结构化，当前不能判断是否满分”。

### 2.6 解析例外和补证任务分别治理

解析例外保留 ADR-007 的通过/不适用/深度复核及审计能力。人工声明“本文件无此条款”必须通过页面内结构化表单提交，至少记录理由、处理人、时间、检索范围/关键词、可选页码和关联候选；不得使用浏览器 `prompt()`。

补证任务按“所缺企业事实/材料”聚合，而不是按每个引用它的条款重复创建。任务保存所覆盖的 `requirement_id[]` 与 `clause_ref[]`，从而既减少重复待办，也不丢失逐条回链。

## 3. 后果

- 需要扩展规则、匹配运行、任务和前端 API 的快照结构；旧结果必须保留并可解释，不能原地改写。
- 首屏更聚焦于真正影响当前决策的资格与资源问题；解析不确定性仍可追溯且继续阻断满分，但不再伪装成“企业缺证”。
- 人员方案搜索会增加计算和交互复杂度，因此必须以确定性约束筛选、快照和可重放为前提，不能由模型自由挑人或用向量分数判定满足。
- 具体字段、迁移、接口、测试和上线顺序见关联技术执行方案；本 ADR 获批并完成对应规格更新前，不改变生产契约或准入公式。

## 4. 评审与生效条件

本 ADR 应至少由经营负责人、投标负责人、资料管理员评审以下业务参数后才可转为“已接受”：

1. 哪些动作在公司制度中确为 `approval_ready` 前置；
2. 项目经理、技术负责人、安全员等岗位的必需角色及可替代规则；
3. 缺证任务的聚合键、默认责任角色和 SLA；
4. 评分分类与“内部满分”对 `not_calculable`/主观评审的处理；
5. 历史解析样本的标识文案、可见范围及禁止审批的测试隔离策略。
