# ADR-003：采集 robots.txt 由「阻断红线」改为「预检留痕」

- **状态**：已接受（Accepted，待法务/经营负责人评审）
- **日期**：2026-09-07
- **关联**：ADR-001、schema §5.2/§5.6、R004、F004、docs/00-项目规则.md §5、AGENTS.md 规则 4

## 1. 背景

2026-09-04 新源探测中，`ccgp-hebei.gov.cn`、`cebpubservice.com` 的 robots.txt 返回 `Disallow: /`。当时 `schema §5.2` 写的是「遵守目标站点 robots.txt；禁止路径不采集」，实现将其作为**运行时硬阻断**，两平台随之被标注「禁用（robots 禁止）」。

复盘定性：robots.txt 是**站点访问许可声明（RFC 9309 行业惯例），不是法律强制**；招标公告按《招标投标法》第 16 条属法定公开信息。是否遵守 robots 是**业务决策**，其语义粒度、来源覆盖收益与风险需由经营者权衡，不应冻结为 schema 不可变红线。原有实现把"决策层"错放进了"实现层"，导致可配置决策退化为硬编码阻断——本 ADR 修正该设置。

## 2. 决策

### 2.1 robots 不再是采集阻断红线

- 抓取动作前仍**读取并解析 robots.txt**（预检），结果**如实记录 `robots_status`（allowed / disallowed / missing / unreachable）供审计复核**，但**不再因 Disallow 跳过源或拒绝抓取**。
- 语义：预检 = 留痕 + 可解释，不阻断。阻断与否由业务侧（源启用登记）判断，不由运行时代码硬判。

### 2.2 保留的红线（不变）

- **schema §5.6 R1：不绕过平台技术保护措施**（无验证码破解/登录态模拟/反爬突破代码路径）。robots 预检放宽不影响 R1：平台若部署验证码/风控等技术保护，抓取如实失败，不破解、不模拟。
- 限频（单源 ≤1 次/5 分钟、全平台 ≤200 次/小时）、透明 UA、不抓取登录/付费/非公开内容、manual_trigger 测试期通道——全部不变。

### 2.3 文档与代码同步

- `schema §5.2`、`AGENTS.md 规则 4`、`docs/00-项目规则.md §5` 改为预检留痕口径。
- `docs/合规数据源清单.md §2.2/§4.1`：ccgp-hebei、cebpubservice 由「禁用」改「可启用（robots 预检留痕，不阻断）」，移入待实测队列，过结构实测后按启用登记流程接入。
- 代码：`check_fetch_allowed` / 搜索执行器的 robots 检查由抛 ComplianceError 阻断，改为记录预检结果不阻断；相关测试同步。

## 3. 验收门槛

- 任一源 robots 返回 `Disallow: /`，搜索/详情导入任务**仍执行抓取**，summary 中 robots 预检状态如实展示（不伪造 populated/fetched 状态）。
- 无任何绕过验证码/登录态/反爬的代码路径；R1 对应测试保持通过。
- 舱内文档（schema/AGENTS/00-项目规则/合规清单/F020/04-修改日志）口径一致。

## 4. 影响与未决事项

- 全站 Disallow 平台被重新纳入待实测（ccgp-hebei、cebpubservice），结构验证后进入启用登记。
- 机器人排除标准仍建议遵循（减轻站点压力、降低被风控概率）：限频与单页抓取策略保持克制，相关策略另有文档。
- 正式抓取前仍建议业务侧确认对 Disallow 站点的抓取容忍度（本 ADR 的"留痕不阻断"是默认值，可由业务在源启用登记中覆写为"阻断"）。
