# ADR-001：投标准入边界（范围变更 + 四层职责 + 满分准入门禁）

- **状态**：已接受（Accepted）
- **日期**：2026-08-25
- **决策人**：AI 产品经理/文档治理 Agent 起草；待公司经营负责人/法务评审确认
- **关联**：`投标信息收集智能体-PRD_v1.md`（v1.0/v1.1）、`投标智能体-智库底座复用方案_v1.md`（骨架树 v1）、`docs/01-需求池.md`（R003-R013、R025）、`docs/03-功能规格/F003、F006、F007、F008、F009、F025`、ADR-002

## 1. 背景与问题

旧 PRD v1.0 定位：信息收集智能体"**只提供情报，不做投标决策**"（§2.1），并将"投标决策、投/不投判断、废标风险分析、编标、签审"列为**非目标**（§2.4）；`advantage`（公司投标优势）子卡仅以占位存在（"待企业资料导入"），未定义匹配逻辑。

新增业务要求（2026-08-25）：
1. 获取招标文件后，系统要将招标资格、人员、业绩、资信及评分要求与公司私有资料逐项匹配和打分；
2. 只有"满分且无硬性缺项"的项目才能进入"待投标审批"；不满足则阻断；
3. 建立可投标项目经理名录并用于匹配；
4. 最终"是否投标"仍由企业经营/投标负责人审批，系统不得自动代表公司作出法律或商业承诺。

**判断：构成范围变化。** 旧 PRD 的"纯事实信息收集层"不包含任何"投/不投"结论；新增"满分才进入投标审批"引入了对企业私有资料的匹配、计分与准入判定。这不是对旧 PRD 的补丁式解释，而是新增一层"资格/资源核查层"。**处理方式：本 ADR 显式登记边界变化，不静默修改旧 PRD，也不声称旧 PRD 已覆盖该能力。**

## 2. 决策内容

### 2.1 四层职责模型

| 层 | 职责 | 是否允许判断 |
|---|---|---|
| 公开情报采集层 | 公告/文件采集、原文保存、事实结构化 | 否，只保留原文事实 |
| 企业私有资料层 | 资质、业绩、项目经理、证书等资料维护 | 否，只维护已验证资料 |
| 资格与资源匹配层 | 按规则逐项匹配、计分、识别缺项 | 是，但仅限可配置规则和证据化结果 |
| 投标审批层 | 决定是否实际投标 | 必须由企业负责人完成 |

- 公开情报层维持旧 PRD 的"纯事实"定位不变：事实卡只记录"公告原文说了什么"，禁止分析断语。
- 新增的匹配/计分只允许出现在资格与资源匹配层，且结果必须是**证据化**的（每条结论回链招标条款 + 企业证据）。
- RAG 三层知识库只负责主要资料入口、候选证据召回和引用组织；其权限、模型出域和索引边界由 ADR-002 约束，不改变本 ADR 的审批边界。
- 投标审批层只属于人：系统输出的是匹配结论与准入状态，不是投标决定。

### 2.2 准入状态机

```text
draft
  → collecting
  → parsed
  → matching
  → blocked_missing_data          （数据缺失/证据不足，默认阻断）
  → blocked_hard_requirement      （响应性硬要求明确不满足）
  → not_qualified                 （明确不满足资格）
  → qualified_full_score          （内部满分准入政策满足，待送审批）
  → pending_bid_approval          （仅进入人工审批，不代表已投标）
  → approved_for_bidding / rejected_by_approver
  → archived
```

迁移规则：

| 迁移 | 触发 | 说明 |
|---|---|---|
| draft → collecting | 人工创建任务并开始导入 | 仅 manual_trigger |
| collecting → parsed | 原文入库并解析完成 | 解析失败 → 人工复核，不自动前进 |
| parsed → matching | 匹配任务启动 | 企业资料不足 → blocked_missing_data |
| matching → blocked_missing_data | 关键证据缺失 | 默认阻断，不推断满足 |
| matching → blocked_hard_requirement | 响应性硬要求证据充分但明确不满足 | 一票否决 |
| matching → not_qualified | 明确不满足资格 | 证据充分的不满足 |
| matching → qualified_full_score | F008 的内部准入政策全满足 | 内部“满分准备度”状态，非评标委员会得分 |
| qualified_full_score → pending_bid_approval | 进入人工审批队列 | 满分不等于自动投标 |
| pending_bid_approval → approved_for_bidding / rejected_by_approver | 投标负责人审批/驳回 | 可附人工豁免 |
| approved_for_bidding / rejected_by_approver → archived | 归档 | 保留审计 |

### 2.3 内部“满分准入”与四类结论（v1.1 修订）

系统必须分别输出资格/响应性核查、当前评分、投标准备度和内部准入四类结论（F008 §2）。它们不能相互替代：资格合格不等于评标得分满分，内部质量评审不等于评标委员会评分，动作就绪不等于已递交或开标。

内部“满分准入”仅是企业把项目送入人工审批队列的保守政策，须同时满足：

1. 所有硬性要求 `satisfied`；证据充分但资格性不满足 → `not_qualified`，响应性硬要求不满足 → `blocked_hard_requirement`；
2. 所有可计算客观计分项按招标评分公式达到其 `max_score`，所有主观项已完成内部质量评审；这不是评标委员会实际得分；
3. 所有关键证据在条款规定的 `as_of` 时点有效、可核验并回链原文；
4. 至少一名项目经理按 F007 的专业、注册、社保/在岗、业绩、在建冲突和可用时点核查通过；
5. 仅“审批前”动作（报名、CA、保证金准备等）已 `ready` 或 `completed`。递交、开标等后续动作不得作为进入审批前提；
6. 招标文件、答疑、补遗、澄清和企业证据均未使匹配结果 `stale`。

任何证据缺失/无法核验进入 `blocked_missing_data`，解析漏项或规则无法执行进入 `manual_review`，不得以缺失替代“不满足”。内部准入为真时才可进入 `pending_bid_approval`，**绝不自动投标**。

### 2.4 数据缺失处置

- 数据缺失（企业资料不足、证据缺失、无法核验）**默认阻断**：进入 `blocked_missing_data` 或待补/待核实队列。
- 系统输出"不可判定/待补材料"，**不得把缺少资料误判为满足或不满足**。
- 缺失字段一律显示"待补/待核实"，禁止编造。

### 2.5 人工豁免

- 豁免范围：可由投标负责人对个别阻断项发起豁免（如证书临期但已受理续期、个别评分项材料在途）。
- 豁免必须记录：授权人、原因、证据、有效期、审批时间。
- 豁免过期自动失效；豁免不改变"满分"定义，只允许带着豁免项进入人工审批视野（是否投标仍由人决定）。

### 2.6 规则版本化与可解释性

- 三类要求（hard/scored/action）的划分、评分公式、满分值、硬性后果、标段/联合体/时点/逻辑关系为**可配置规则**，规则版本化；历史项目保留当时规则版本。
- 招标文件、答疑、补遗或澄清影响要求、评分或期限时，必须生成新版本并使旧匹配结果失效后重算。准入结果须可解释（见 F008），展示四类结论、总分/不可计算项、阻断/待补/复核、条款、证据及经理匹配。

## 3. 影响评估

| 影响对象 | 影响 |
|---|---|
| 旧 PRD §2.1/§2.4 | 维持原状（历史基线）；本 ADR 登记范围扩展，不改写 |
| advantage 子卡 | 由占位升级为正式匹配矩阵（资质/业绩/项目经理），引用企业私有库 |
| schema | 需新增匹配域、项目经理域、准入状态域（Iteration 1 审计扩展） |
| 数据治理 | 企业私有资料入 Material 治理（F003），分层隔离 |
| 权限 | 新增四层权限矩阵（公开层/私有层/匹配层/审批层） |
| 合规 | 不新增采集面；私有资料使用需法务确认；个人信息（项目经理）最小化 |

## 5. 替代方案与理由

| 方案 | 评估 |
|---|---|
| A：维持纯事实层，不做匹配 | 不满足新增业务要求，拒绝 |
| B：在信息收集层内直接做投/不投判断 | 污染纯事实层、越权决策，拒绝 |
| C：新增"资格/资源核查层"，满分进人工审批（本方案） | 满足要求且边界清晰：公开层纯事实、匹配层规则化、审批层在人，采纳 |
