# 推送卡片模板（FR7 · 飞书/邮件）

> 推送前过 G4 门禁：时效优先级已标注、匹配规则命中、个人信息脱敏、原文链接可点击、**招标文件获取入口已提取标注**（schema §6.4.1 通道①）、**链接浏览器级可达性已复检**（2026-08-17 A 修复：curl 200 不代表浏览器可打开）。
> **卡片规格 = 情报库主卡同等详细，表头一律中文**（2026-08-13 优化）。
> 只展示结果不展示过程；每条必须可溯源（原文链接）。

## 链接可达性标注（G4 前置，2026-08-17 新增）

> 背景：ggzy.gov.cn / ebidding.hebtig.com / eps.ctg.com.cn / chnenergybidding.com.cn 等平台
> 服务器 TLS 配置老旧，拒绝现代浏览器（Chrome/Safari/飞书内置）默认的 TLS 1.3 握手
> （`ERR_CONNECTION_CLOSED` → "无法访问此网站"），但 curl/urllib（协商 TLS 1.2）返回 200。
> 复检必须用 `scripts/check_links_browser.py`（Chrome headless 实测），不能用 curl 判定。

| 复检结果 | 卡片标注 | 附备选入口 |
|---------|---------|-----------|
| ✅ browser_ok | 正常「原文链接（可点击）」 | 不需要 |
| ⚠️ browser_blocked / browser_fail | 「⚠️ 链接在当前浏览器可能打不开（平台 TLS 兼容问题，内容存在）」 | **必须附**：平台首页 + 搜索公告标题关键词 |
| ❌ unreachable | 「❌ 链接不可访问」 | 附平台首页，标注"待人工验证" |

复检命令：`python3 scripts/check_links_browser.py "<原文链接>" "<入口链接>"`（输出三态 + JSON）。

## 飞书卡片（推荐格式）

> **展示规则（2026-08-17 用户要求）**：**有值的字段才展示**；缺失字段**不显示在卡片正文**，
> 统一汇总到文末「【待补充字段】（公告原文未载明，不编造）」清单（每条公告一行，列出缺失字段名）。
> 整段无任何有值字段 → 该段不显示。字段缺失不代表系统错误，是公告原文未载明。
> **排版规则（2026-08-18 v0.3.1，参考 Google/Facebook 通知风格）**：每条公告标**序号**（1. 2. …），
> 卡片间以单空行分隔，分组间不空行（分隔线即视觉分隔），**去多余空行**；结构与字段内容不变。

## 匹配命中标注（G4 前置）

| 检查项 | 状态 |
|--------|:--:|
| 时效优先级已标注（P0/P1/P2，§2.2.7 重算） | ☐ |
| 匹配规则命中（关键词/资质/区域/金额） | ☐ |
| 个人信息已脱敏（联系人电话/邮箱打码） | ☐ |
| 原文链接浏览器级可达性复检（check_links_browser.py，2026-08-17 起替代 curl 判定） | ☐ |
| ⚠️ 复检为 blocked 时已附备选入口（平台首页 + 公告标题关键词） | ☐ |
| 纯事实红线（无"值得投"等分析断语） | ☐ |
| 项目状态 = active 且报名未截止 | ☐ |

> 全部 ☐ 通过才可推送；任一未过 → 回 G4 auto_action 修复或人工复核。
> 已过报名期（T > deadline_signup）的项目**不推送**（§2.2.7 不予采纳）。
